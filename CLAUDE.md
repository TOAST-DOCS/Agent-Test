# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo actually is

Not a product codebase — a **test fixture** for the NHN Cloud translation pipeline. It holds:

- `ko/`, `en/`, `ja/` — parallel Markdown docs (based on NHN Cloud "Compute > Instance") used as translation input/output samples.
- `archive/{alpha-origin,aligned,alpha-origin-40pct,fill-stub,fix-tables}/{ko,en,ja}/` — frozen seed states that the restore scripts copy back into `ko/en/ja/` before each e2e run. `alpha-origin` is the canonical seed; `aligned/` is a pre-aligned `public-api.md`; `alpha-origin-40pct/` is a size-reduced variant used by the re-translate flow; `fill-stub/` holds `fill-stub-sample.md` with its stubs intact (see below).
- `{ko,en,ja}/fill-stub-sample.md` — fixture for **빈 번역 채우기** (`translate/translate_fill_stubs.py`; dashboard '빈 번역 채우기' → Jenkins translate job in FILL mode). ko carries the full source; en/ja carry the same outline with five fillable stubs each — three `<!-- TODO: translate body -->` (plain prose, a table, a fenced code block) and two `<!-- TODO: translate -->` heading stubs (one `##`, one nested `###`, both still Korean). Two controls bracket them: `#fill-stub-untouched` / `#fill-stub-tail` are already translated and must come back **byte-identical**, and `## 앵커가 없는 섹션` deliberately carries no `<a id>` — a fill run must skip it and report it, never guess. All three languages share one heading outline, so the `pre-align:aligned` sig is identical across ko/en/ja and `/compare-headings` stays green. A successful fill consumes the stubs; `scripts/restore-fill-stub-sample.sh` puts them back for the next round. Not registered in `ko/nav.yml` — it is a pipeline fixture, not a published guide.
- `{ko,en,ja}/fix-tables-sample.md` — fixture for **깨진 표 정비** (`translate/translate_fix_tables.py`; dashboard 🧹 문서 정비 '깨진 표 정비' → Jenkins translate job in FIXTABLES mode). The sibling of the fill-stubs fixture, inverted: instead of sections that are EMPTY, it carries sections that are PRESENT with tables that no longer match ko, in the three shapes the tool detects — `#fix-tables-missing` (the table is gone from en/ja, so the per-section table COUNT differs), `#fix-tables-shifted` (row and column count match ko but the first column's identifiers were overwritten with format names — the Transit-Hub shape), `#fix-tables-rows` (one identifier row dropped). Three controls bracket them and must come back **byte-identical**: `#fix-tables-untouched` (a healthy table), `#fix-tables-tail`, and `#fix-tables-prose-keys` — whose table has a prose first column (no identifier rows, equal counts, so nothing observable is wrong) and which additionally holds `### 앵커가 없는 하위 섹션`, an id-less child heading with a broken table under it. That last one is the sharpest control: the anchor map attributes that table to the section above, but the rebuild unit stops at the child heading, so the tool must report the section as skipped rather than rebuild the wrong body. All three languages share one heading outline, so the `pre-align:aligned` sig is identical across ko/en/ja. Fixes land on the e2e session branch, so alpha keeps the divergence and the fixture is reusable; `scripts/restore-fix-tables-sample.sh` restores it if alpha's copy is damaged. Not registered in `ko/nav.yml` — it is a pipeline fixture, not a published guide.
- `{ko,en,ja}/fix-links.md` — fixture for **link fix** (`dashboard/viewer/link_fix.py`, Jenkins `fix-links`). One deliberately malformed link per deterministic rule (`self-link`, `relativize` as a github-blob URL and as a repo-rooted path, `lang-dir`, `nested-frag`, `heading-frag`), two links whose repair cannot be verified (a missing document and a dead anchor — these must be **reported, not fixed**), and controls that must not move: five healthy links — including `./overview/#pricing`, the deployed-URL shape pointing at *another* doc, which is the corpus's dominant practice and must never be "relativized" — plus two inside a code fence. All three languages carry the same link set modulo the locale segment, so a `lang-parity` verification over the repo stays clean. Repairs land on the e2e session branch, so alpha keeps the broken links — that is deliberate: `/link-check` on Agent-Test alpha reports them as NotOK forever, which is what makes the fixture reusable.
- `scripts/` — the real "code": bash scripts that drive an external dashboard/Jenkins pipeline (fix-heading-syntax → align → ko-review → translate) and verify results with `scripts/check_docs_align.py` (structure) plus the `claude` CLI (semantics, ko-review only).
- Documentation in `scripts/dashboard-api.md` describes the dashboard endpoints these scripts hit.
- `.claude/skills/split-docs-by-year/` — project skill (`/split-docs-by-year`) that splits a date-accumulating doc such as `release-notes.md` into `<lang>/<stem>/<year>.md` reassembled with `include-markdown`. Its `scripts/split_by_year.py` carries the guards that make the split safe (anchor pull-back, year-contiguity, round-trip equality, `--check <rev>`); copy the directory into another docs repo to reuse it there.

There is **no build, no test framework, no lint**. The e2e scripts are the tests.

## Branch conventions

- `alpha` — canonical branch. **Must stay clean** — e2e scripts default to spinning up a fresh session branch instead of committing here. Only script/doc edits belong on `alpha`.
- `beta` — kept in sync with `alpha` for downstream consumers.
- `e2e/<UTC-timestamp>` — a session branch created by `e2e-align-and-translate.sh` at start of each run. All pipeline PRs/commits happen here.
- `translate-test/<ts>` — head branch of the ko-mutation PR that a session opens; created by `create-translate-test-pr.sh`.
- `translate/translate-test/<ts>-<hash>-<ts>` — head branch of the translation-result PR produced by the translate Jenkins job.
- `pre-align/fix-headings-*`, `pre-align/fix-heading-syntax-*` — head branches of PRs produced by the Jenkins align / fix-heading-syntax jobs.
- `e2e-fillstubs/<ts>` · `e2e-splitdocs/<ts>` · `e2e-fixlinks/<ts>` · `e2e-fixtables/<ts>` — session branches of the four single-purpose e2e scripts. Each is cut from `alpha`; the PRs their jobs open have head branches `fill-stubs/<ts>` · `split-docs/<ts>` · `fix-links/<ts>` · `fix-tables/<ts>` (named by the tool, not the harness), which is how the scripts find and clean them up.
- `e2e-preserve/<ts>` — session branch of `e2e-preserve-existing.sh`, cut from `alpha`. Its head branches are `translate-test-preserve/<ts>` (the ko mutation) and `translate-test-preserve-control/<ts>` (the `--no-preserve-existing` control run), plus whatever `translate/translate-test-preserve*` branches the translate job opens. Unlike the other single-purpose e2e scripts this one has **no resident fixture**: the document has to exceed Claude Code's 25,000-token `@file` limit to test anything, so the script generates a ~200-section doc at run time and commits it to the session branch only.
- `alpha-origin` (remote) — historical reference; the *directory* `archive/alpha-origin/` is what restore uses, not this branch.

**Every PR an e2e run produces carries the `e2e` label** — the ko-mutation PR and the concurrent A/B PRs get it at `gh pr create` time, and the PRs the Jenkins jobs open (translate / align / fix-heading-syntax) get it right after the harness detects them. `scripts/e2e-label.sh` holds the two helpers (`e2e_ensure_label`, `e2e_label_pr`); it creates the label on first use and never fails a run over a labeling error. This matters because verification failures deliberately leave PRs open, so the open-PR list mixes fixture output with anything a human opened — `gh pr list --repo TOAST-DOCS/Agent-Test --label e2e` separates them. Labeling helpers print to **stderr**: several callers parse a PR URL off stdout.

## Running the e2e pipeline

Prerequisites (all must be on PATH): `git`, `gh` (logged in), `curl`, `python3`, `claude` (Claude Code CLI).

Env: `load_env.sh` at repo root exports `DASHBOARD_BASE_URL` and `DASHBOARD_API_TOKEN`. **It is untracked and holds a real token — never commit it.**

```bash
source ./load_env.sh

# Full round1 e2e (~25-35min; it was ~2h before the deterministic verifier).
# Creates e2e/<ts> from alpha, runs the whole pipeline
# on it, merges everything into that session branch. Alpha is not touched.
bash scripts/e2e-align-and-translate.sh
# → prints "E2E_BASE_BRANCH=e2e/<ts>" as a marker for the wrapper

# Round2 — 2nd-generation drift on the same session branch (~1h)
bash scripts/e2e-translate-round2.sh --base-branch e2e/<ts>

# Override the auto-created branch (e.g., to re-run on alpha directly)
bash scripts/e2e-align-and-translate.sh --base-branch alpha
```

Common flags for both e2e scripts: `--engine api|cli`, `--model haiku|sonnet|opus`, `--tm-top-k N`, `--chunk-workers N`, `--guidelines-variant-{en,ja} <v>`, `--verify py|fable`. Round1 also has `--align-v2 / --no-align-v2` and `--from-aligned <branch>` (skip steps 2–9, see "Suite runtime shape"). Round2 requires `--base-branch` when the session branch isn't `alpha`.

`scripts/e2e-suite.sh` is the runner for all of the above (`all` = every plan except `round2`, which needs a manual merge first). `scripts/e2e-concurrent-prs.sh` (`concurrent` plan) is the one e2e that never touches the dashboard — it reproduces the concurrent-ko-PR scenario (A opened, B opened+merged+translated, then A merged and translated) with the **local** `translate_pr.py` and checks that A's translation preserves B's new section / table row.

`scripts/e2e-fill-stubs.sh` (`fill-stubs` plan) verifies the **fill-stubs** path — `translate_fill_stubs.py`, which scans a whole branch for pre-align's `<!-- TODO: translate* -->` markers and fills each from the ko section sharing its `<a id>`. It runs against the committed `{ko,en,ja}/fill-stub-sample.md` fixture (five fillable stubs per language — plain prose, a table, a fenced code block, a `##` heading stub and a nested `###` one — plus an **id-less stub as a negative control**) and judges by byte comparison only: the filled section must lose the marker and carry no Hangul, the table must keep ko's column/row count, the code fence must be byte-identical to ko's, the heading stub must keep ko's level and `<a id>`, everything outside the filled sections must be byte-identical to the base, and the id-less stub must be left alone and reported as skipped in the PR body. No LLM verifier: this tool breaks structurally (wrong ko section, rewritten anchors, promoted heading level, whole-file EOL churn), not semantically. The fixture is committed rather than seeded because the seeding code had to imitate pre-align's stub shape — and its "no fences, no tables" selection filter excluded exactly the shapes that actually break. Default `--translate local`; `--translate api` drives the dashboard `/api/fill-empty` → Jenkins path instead.

`scripts/e2e-split-docs.sh` (`split-docs` plan) verifies **release-note splicing** — `pre-align/split_docs_by_year.py`, which cuts `<lang>/release-notes.md` into `<lang>/release-notes/<year>.md` and leaves the original path holding its header plus mkdocs `include-markdown` directives. It runs on alpha's real `release-notes.md` (91 date sections → 11 year files per language) rather than a fixture, because a hand-made fixture loses the shapes that matter: anchors straddling a year boundary, date headings with and without `{ #id }`, per-language line-count drift. The judgement is a **round trip** — expand the parent's includes in order and it must equal the original content-for-content — plus anchor-order preservation, all-or-nothing across ko/en/ja, and a valid `pre-align:aligned` marker on every year file *and* the re-stamped parent. No model is involved at any point.

`scripts/e2e-fix-tables.sh` (`fix-tables` plan) verifies **깨진 표 정비** — `translate/translate_fix_tables.py`, the fill-stubs job's sibling: it scans a branch's en/ja against ko and rebuilds, from ko, the section bodies whose TABLES diverged. It runs against the committed `{ko,en,ja}/fix-tables-sample.md` fixture and judges by byte and structure comparison only: each rebuilt section must end up with ko's table count and ko's (columns, rows) per table, must carry every ko identifier row again, must keep its `<a id>` and heading lines byte-identical, and must match ko's block shape; everything outside the rebuilt sections — including the three controls — must be byte-identical to the base; and the PR body must name each rebuilt anchor with its reason, report the id-less-child section as skipped, and carry per-section before/after Docs Preview links pinned to commit SHAs. No LLM verifier: like fill-stubs, this tool breaks structurally (a wrong verdict on a healthy table, a missed shifted column, rewritten anchors, a rebuild that silently drops a row), not semantically. Default `--translate local`; `--translate api` drives the dashboard `/api/fix-tables` → Jenkins path instead (that mode skips the dry-run rule).

`scripts/e2e-fix-links.sh` (`fix-links` plan) verifies **link fix** — `dashboard/viewer/link_fix.py`, the only link tool that writes to product repos. It runs against the committed `{ko,en,ja}/fix-links.md` fixture, which seeds one link per deterministic rule (`self-link`, `relativize` ×2, `lang-dir`, `nested-frag`, `heading-frag`), two links whose repair cannot be verified, and controls that must not move (five healthy links — one of them the deployed-URL shape `./overview/#pricing` that the corpus uses everywhere — and two inside a code fence). The judgement builds the **expected file** by applying the six known rewrites to the base and demands a byte-exact match — which checks the repairs, the controls, the fence and the "only link targets change" guarantee in one comparison. It runs with the `/link-check` page's **⭐ 권장 옵션** (whole repo · DRY-RUN off · `engine=env` · `lang-parity`+`cross-context`), because DRY-RUN-off is this job's only dangerous path and an e2e that never takes it is not testing the job people actually run.

`scripts/e2e-preserve-existing.sh` (`preserve` plan) verifies that **preserve-existing actually reaches the model** — `translate/app/preserve_slice.py`. `--preserve-existing` turns a full re-translation into a minimal-diff rewrite by giving each chunk the existing translation as a baseline, and on the CLI engine that baseline travels as an `@file`: Claude Code silently DROPS an attachment above **25,000 tokens** (measured 24,976 → seen, 25,045 → not seen; `is_error: false`, `num_turns: 1`, empty stderr) and `--allowedTools Write` means the model cannot Read it either. `retranslate-20260903-1` (translate #490, SMS `ko/api-guide-v2.2.md`) logged `Created preserve file for en: … (236704 chars)` **64 times** while the model received nothing, so the run re-translated the whole document under a "reuse existing wording" instruction and still looked green — the defect was found by wondering why it was slow, not by any failure. That is why the fixture must be BIG: the script generates a ~200-section anchored API-guide-shaped document at run time (en ≈ 118,000 chars ≈ 38,000 tokens with the preamble) and refuses to run if the estimate lands under the limit, because a small fixture passes on the pre-fix code and tests nothing. It then changes **one section's ko prose** and judges the OUTPUT, not the log: ≥90% of the untouched sections must be byte-identical in both en and ja (a ratio, not zero-tolerance, so one model wobble is not a failure — an unapplied preserve sits near 0%), the changed section must actually change (a mirror that swallows real work is the opposite failure), and a **control run with `--no-preserve-existing`** on the same input must churn strictly more, which is what separates "preserve worked" from "chunking got lucky". Two log rules back it up: the per-chunk `Preserve-existing: using this chunk's own section` line must appear for each language, and neither `Preserve-existing DISABLED` nor a whole-document block may appear.

`scripts/e2e-docs-url-locale.sh` (standalone, not a suite plan) verifies the **locale of deployed docs deep links** — `translate/app/postprocess.py :: rewrite_links`. A deployed URL carries the locale twice (`https://{host}/{site_lang}/{slug}/{doc_lang}/{stem}/#a`) and the two slots must move together: a mismatched pair renders NHN Cloud's landing page with HTTP 200, so it is a dead link no status check can see. It seeds one paragraph carrying four link kinds — an absolute public docs URL, an absolute **gov** docs URL, a site-root shorthand and a genuinely external URL — into ko/en/ja (en/ja seeded **already correct**, because the second defect only shows when the pipeline is handed a right answer to ruin), then changes **only the fragment** of the ko absolute URL, which is exactly the shape that shipped Storage-Online-NAS#98's 12 wrong-language links. Eight rules: both slots land on the target language, the new fragment is reflected, **no mismatched pair exists anywhere in the file**, the gov URL stays Korean (region guides ship ko only, so localizing one invents a 404), the site-root shorthand and the external URL keep today's behaviour, and a Korean control sentence in the same paragraph is actually translated. No fault injection: the pre-fix behaviour is deterministic — a ko absolute URL inside a re-translated unit reproduced it 100% of the time.

`scripts/e2e-link-target-mirror.sh` (standalone, not a suite plan) verifies the **link-target mirror (M6)** — `translate/app/link_edits.py`, which stops a ko line whose only change is a LINK TARGET from re-translating the unit that holds it. Link fixes are the most common ko change in this pipeline (4 of the 6 ko PRs that translated on 2026-08-31), and the run that produced two of that day's reported defects is the fixture's model: Container-Kubernetes#498 → #499 changed 9 link-target-only ko lines whose 18 links (9 × en/ja) were **already correct in en/ja**, and the re-translation dropped a `can` from `en/user-guide.md` (可能 → 指示) and re-worded a link label away from its own target heading. Four sections, each with its own anchor so one case's re-translation cannot rewrite another's: **A** en/ja seeded with the NEW fragment (the 18/18 shape) must come back **byte-identical**; **B** seeded with the OLD fragment must have the fragment substituted and every other byte of the line preserved; **C** written as a fully-qualified URL where ko uses site-root shorthand cannot be located, so it must fall through to a normal re-translation *without* inventing a mismatched locale pair; **D** a link-free Korean paragraph must still be translated — the real risk of this change is a mirror that swallows real work. Rule (6) greps the `Link-target mirror (en|ja): 2 ko line(s) — 1 … already correct, 1 substituted, 1 line(s) left to the splice` log line, so the *mechanism* is checked and not just the outcome; it is absent entirely before the fix. Rule (8) reads the **summary comment**, not the PR body: the body's '무관한 표 수리' section is for changes outside the reviewer's own ko diff, and the mirror by definition only touches link targets that belong to a ko line the reviewer changed. Runs with `--base-branch <session>` because the mirror needs a real `old_ko` signal — the default (`base_branch` = the ko PR's head) makes `old_ko == new_ko`. Measured 2026-09-01 against the M6 branch: **16/16 rules pass** (translation PR #745).

`scripts/e2e-retranslate-align-and-translate.sh` is a variant of round1 that appends a full re-translation of `public-api.md` to the align PR (using `/api/translate/file` and a 40%-reduced fixture for speed).

## Design points to preserve

- **Round1 auto-merges** translation-PR → ko-PR head → session branch on `ALIGNMENT: OK`. **Round2 does not** — its translation PR is left OPEN with the fable verification result as a comment. This asymmetry is intentional (round2 output is for human review).
- Round2 detects the translation PR by **head-branch prefix** `translate/<ko_head_ref>-`, not by base. This is because round2 merges its ko-change PR *before* triggering translate, so the resulting PR opens against the session branch rather than the ko-PR branch.
- `create-translate-test-pr.sh` mutates only `ko/` files (en/ja are deliberately left as drift) and refuses to run with a dirty working tree. Its `PLAN_ROUND2` uses `add_section_no_id` / `add_subsection_no_id` — round2 adds new sections **without** anchor ids so the translate job's auto-assignment is exercised end-to-end; the round2 fable prompt has a dedicated "(5) anchor id 자동 할당 검증" check for this.
- Session branches are left behind after each run for debugging. Manual cleanup:
  ```bash
  gh pr list --repo TOAST-DOCS/Agent-Test --search "base:e2e/<ts>" --state open
  gh pr close <N> --repo TOAST-DOCS/Agent-Test --delete-branch
  git push origin :e2e/<ts>
  ```

## Verification model

Every e2e stage that produces a PR (align, translate) is gated by a checker that inspects the PR's head branch in a worktree and prints `ALIGNMENT: OK` or `ALIGNMENT: FAIL` on its **last line**. The wrapper greps that line (`grep -q '^ALIGNMENT: OK'`) to decide merge vs. leave-open — keep that contract intact.

The gate is **`scripts/check_docs_align.py`** (default, `--verify py`), a deterministic implementation of the six structural rules the old fable prompt asked for:

1. heading level order identical across ko/en/ja
2. anchor id order identical (`<a id>`/`<a name>`/`<tag id>` and heading `{ #id }`)
3. table count + per-table data row count identical; orphan table rows (a `|`-run with no separator) fail
4. rows keyed by a language-independent identifier (version/code token) keep the same key set and order
5. no Korean left in en/ja outside fences/inline code — with `scripts/known_korean_leftovers.txt` listing literals that are *expected* to stay (reported as `~`, not FAIL)
6. every row of a table has the header's cell count (a wider row silently loses cells when rendered)
7. `--markup` (markup-churn only): if ko has no bare `<br>` left, neither may en/ja — i.e. cosmetic markup mirroring actually ran

It enumerates targets by walking `ko/` **recursively** and keeping every `.md` (non-variant) that exists at the same relative path in `en/` and `ja/` — so include-assembled bodies in a subfolder are checked, not just the top-level page that includes them. `EXCLUDED_STEMS` drops a stem *and* its same-named subfolder from that enumeration (currently `release-notes`, whose en/ja fixture was never aligned with ko and so only ever produced noise); the run prints what it skipped. `--files` accepts `ko/foo.md`, `foo.md`, or `release-notes/2016.md`, and overrides the exclusion — that's the way to check a `release-notes/<year>.md` while fixing its drift.

**The translate gate checks the plan's files, not the whole tree.** `ko/` is a shared fixture drawer: each e2e owns a few documents and the rest belong to some other test. Some of those are *supposed* to be out of alignment — `fill-stub-sample.md` exists precisely to be filled by `e2e-fill-stubs.sh`, so its en/ja carry `<!-- TODO: translate -->` and untranslated ko headings, and a tree-wide sweep fails rules (3) and (5) on it forever, in every plan, for a condition no plan caused. So step 17 passes `--files` scoped to the running plan, plus `--apply-exclusions` so a plan list that happens to name an `EXCLUDED_STEMS` document (table-suite mutates `release-notes.md`) doesn't smuggle the permanent-FAIL fixture back in through the override. The list has exactly one source of truth — the `PLAN_*` arrays in `create-translate-test-pr.sh`, emitted by `--plan <name> --list-files` as the union of the plan's mutated ko paths and the ko counterparts of whatever `STALE_ROWS`/`STALE_DROP_COLS`/`STALE_TABLES` stale-ifies (a stale-ified doc is what reconcile has to repair, so it must be checked even though ko never changed). Deriving it beats hardcoding a second list per plan, which would drift the first time a mutation moves. If the emitter returns nothing the wrapper warns and falls back to the whole tree — checking too much beats checking nothing. What this gives up: step 17 no longer notices a translate run that damaged a file outside its plan. Step 8 still sweeps the whole tree (rules 1–2) after align, which is the stage that legitimately rewrites every document.

It replaced a `claude -p --model fable` agentic check that spent 15–25 min per stage reading the same 11 documents; the Python version takes ~0.05 s and cannot drift between runs. `--verify fable` still runs the old prompt (kept in the scripts) when a semantic check is wanted. `e2e-korean-review.sh` is unchanged — its check *is* semantic (does the review make sense?) and still uses fable, with the `KO_REVIEW: OK|FAIL` contract.

## Suite runtime shape

`scripts/e2e-suite.sh` runs plans sequentially. Two things keep it from re-paying fixed cost:

- **Deterministic verification** (above) — the two big LLM checks per plan are gone.
- **align prologue reuse** — steps 2–9 (restore → fix-heading-syntax → align → verify → merge) produce the same result every time because the fixture is frozen, so the suite runs them for the **first** align-based plan only, then passes that snapshot branch (`E2E_ALIGNED_BRANCH=<session>-aligned`) to the rest via `e2e-align-and-translate.sh --from-aligned`. Each plan still gets its own session branch, so plans can't interfere. `--no-reuse-align` restores per-plan prologues.

Measured Jenkins-side cost per plan (unchanged by the above): fix-heading-syntax ~1 min, align-heading 3–4 min, ko-review 0.5–2 min, translate 8–15 min. Trimming fixtures therefore buys much less than removing the LLM checks did — `archive/*/public-api.md` was cut to its first five `##` sections (2126 → 1086 lines) because it was pure repetition of the same endpoint shape; the rest of the fixture is left alone on purpose (it carries the align drift, the markup churn counts, and the mutation anchors).

## Dashboard API contract

`scripts/dashboard-api.md` is the authoritative reference for the endpoints the e2e scripts call (`/api/fix-heading-syntax`, `/api/align`, `/api/ko-review`, `/api/translate`, `/api/translate/file`, `/api/jobs/<id>`). Consult it before adding new API calls or changing request bodies.
