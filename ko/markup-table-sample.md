# 표 마크업 이상 상태 모음 — 소스 파서와 렌더러가 표의 끝을 다르게 볼 때

표의 끝을 두 파서가 다르게 본다. 우리 도구는 `|` 로 시작하는 줄까지를 표로 보고, 사이트가
쓰는 python-markdown 은 **빈 줄이 나올 때까지 전부 행으로** 읽는다. 둘이 갈리는 자리에서
독자는 **저자가 쓰지 않은 행**을 받는다. 이 문서는 그 모양들을 한자리에 모아 둔 픽스처다.

판정은 뺄셈이다 — `python-markdown 이 만든 행 − 저자가 행으로 쓴 줄`. 멀쩡한 표에서는 0 이고,
빨려 들어간 줄의 개수와 정확히 같다. 렌더만 봐서는 판정할 수 없다: 문장 하나가 든 행은 어떤
문서에서는 정상이고, 그 둘을 가르는 것은 "저자가 그 줄을 행으로 쓰지 않았다" 뿐이다.

수리는 두 가지뿐이고 둘 다 **줄바꿈 하나**만 건드린다. 셀 안에서 끊긴 행은 그 줄바꿈을 지우고
(M7), 표 뒤에 빈 줄이 없어 딸려 들어간 줄은 그 앞에 빈 줄을 넣는다(M8). 고칠 수 없는 모양은
고치지 않고 보고만 한다 — 빈 줄을 잘못 넣으면 아래 행들이 통째로 표 밖으로 나간다.

heading 이 빨려 들어가면 **heading 이기를 그만둔다** — 목차에서 빠지고 자동 생성 anchor 도
만들어지지 않는다. 표가 지저분해지는 것보다 이쪽이 더 아프다.

| # | 소스 | 독자 화면 | 판정 |
|---|---|---|---|
| 1 | 표 뒤에 빈 줄이 있음 | 표 그대로 | 정상 (대조군) |
| 2 | 셀 안에 줄바꿈 (행이 중간에서 끊김) | 잘린 행 + 문장만 든 빈 행 | **결함 — M7 자동 수정** |
| 3 | 표 뒤 빈 줄 없음 + `###` | 제목이 **표의 행**이 되고 목차에서 사라짐 | **결함 — M8 자동 수정** |
| 4 | 표 뒤 빈 줄 없음 + `<a id>` + `###` | 빈 행 하나 + 제목 행 하나 | **결함 — M8 자동 수정 (한 편집)** |
| 5 | 표 뒤 빈 줄 없음 + 인용구 | 인용구 줄들이 전부 행이 됨 | **결함 — M8 자동 수정** |
| 6 | 파이프 없이 쓴 표 | 정상 렌더 | **정상 — 손대면 안 됨** |
| 7 | 템플릿 문법(`{{ }}`)이 든 표 | 빌드 때 전개됨 | **정상 — 판정하지 않음** |
| 8 | 표 **중간**이 망가짐 (뒤에 행이 더 있음) | 문장 행이 표 가운데 끼어듦 | **보고만** |
| 9 | 표 바로 뒤에 코드 펜스 | 펜스가 블록을 끊음 | 정상 (대조군) |

***

## 1. 정상 — 표 뒤에 빈 줄이 있다 (대조군)

| 속성명 | 기본값 | 자료형 | 설명 | 비고 |
| --- | --- | --- | --- | --- |
| 버킷 | - | string | 데이터를 읽을 버킷 이름을 입력합니다. |  |
| 리전 | - | string | 저장소에 설정된 리전 정보를 입력합니다. |  |

이 문단은 빈 줄 뒤에 있으므로 표에 딸려 들어가지 않는다.

## 2. 셀 안에 줄바꿈이 들어간 행 — M7

아래 표의 `리전` 행은 설명 셀 한가운데에서 줄이 끊겨 있다. 소스 파서는 `|` 로 시작하지 않는
다음 줄에서 표가 끝났다고 보지만, python-markdown 은 그 줄까지 행으로 읽어 **속성명 칸에
설명 문장만 들어간 행**을 하나 더 만든다.

| 속성명 | 기본값 | 자료형 | 설명 | 비고 |
| --- | --- | --- | --- | --- |
| 버킷 | - | string | 데이터를 읽을 버킷 이름을 입력합니다. |  |
| 리전 | - | string | 	저장소에 설정된 리전 정보를 입력합니다. |  |
| 비밀 키 | - | string | S3가 발급한 자격 증명 비밀 키를 입력합니다. |  |

## 3. 표 뒤에 빈 줄이 없고 제목이 이어짐 — M8

아래 표 다음에 빈 줄이 없다. 제목이 표의 마지막 행이 되고, **목차에서도 사라진다**.

| 항목 | 값 |
|---|---|
| 최대 크기 | 10 |

### 3-1. 이 제목은 표의 행이 된다

이 문단은 빈 줄 뒤라 정상이다.

## 4. 앵커와 제목이 함께 빨려 들어감 — M8

이 리포 관례대로 `<a id>` 를 제목 위에 두면 **두 줄**이 함께 딸려 들어간다. 앵커는 표 셀 안에서
살아남아 링크는 계속 동작하지만, 제목은 사라진다. 수리는 편집 **하나**로 둘을 함께 푼다.

| 항목 | 값 |
|---|---|
| 재시도 횟수 | 3 |

<a id="markup-table-swallowed-anchor"></a>
### 4-1. 앵커와 함께 빨려 들어간 제목 { #markup-table-swallowed-anchor }

이 문단은 빈 줄 뒤라 정상이다.

## 5. 인용구가 표의 행이 됨 — M8

| 항목 | 값 |
|---|---|
| 대역 | 10.0.0.0/16 |

> CIDR 는 링크 로컬 대역(169.254.0.0/16)과 겹칠 수 없습니다.
> Pod 네트워크와 서비스 네트워크 대역도 겹칠 수 없습니다.

## 6. 파이프 없이 쓴 표 — 손대면 안 된다 (대조군)

선행 파이프는 선택이다. 표 전체를 이렇게 쓴 문서에서는 **행과 군더더기 줄을 가를 신호가 없어서**
판정 대상으로 삼지 않는다. 아래는 정상 렌더이고 한 바이트도 바뀌면 안 된다.

스토어 | 입력 문자열
------------- | -------------
Google Play Store | Google
Apple App Store | Apple

## 7. 템플릿 문법이 든 표 — 판정하지 않는다 (대조군)

디스크의 마크다운이 곧 배포되는 마크다운이 아니다. `{{#each}}` 앞에 빈 줄을 넣으면 그 루프가
만드는 표가 쪼개진다.

| 리전 | 엔드포인트 |
|---|---|
{{#each regions}}
| {{this.name}} | {{this.endpoint}} |
{{/each}}

## 8. 표 중간이 망가짐 — 보고만

행이 아닌 줄 **뒤로 저자가 쓴 행이 더 나온다**. 여기에 빈 줄을 넣으면 아래 행들이 통째로 표 밖으로
나가므로, 독자가 받는 것이 더 나빠진다. 고치지 않고 보고만 한다.

| 번호 | 항목 | 예시 |
|---|---|---|
| 1 | 요청 속도 제한 | 초당 5회로 제한 |
limit_req_zone $binary_remote_addr zone=req:10m rate=5r/s;
| 2 | 캐싱 | 동일 요청 캐싱 |

## 9. 표 바로 뒤에 코드 펜스 — 정상 (대조군)

펜스가 블록을 끊으므로 표는 제자리에서 끝난다.

| 항목 | 값 |
|---|---|
| 포트 | 8080 |
```bash
curl -s http://127.0.0.1:8080/health
```
