<a id="compute-instance-overview"></a>
## Compute > Instance > 概要 { #compute-instance-overview }

インスタンスは、仮想 CPU、メモリ、ルートブロックストレージで構成される仮想サーバーです。このサーバーに顧客のサービスやアプリケーションをインストールし、NHN Cloud が提供するさまざまなサービスを組み合わせて使用します。

<a id="components"></a>
## インスタンス構成要素 { #components }

インスタンスを構成する要素は次のとおりです。

- **イメージ**: インスタンスのオペレーティングシステムを格納する仮想ディスク
- **タイプ (flavor)**: インスタンスの仮想ハードウェアパフォーマンス
- **可用性ゾーン (AZ、availability zone)**: インスタンスが作成される物理的な場所
- **キーペア (key-pair)**: インスタンスのアクセス手段として使用されるキー
- **セキュリティグループ (security groups)**: インスタンスのネットワークセキュリティ設定
- **ネットワーク**: インスタンスが接続される仮想ネットワーク

この情報に応じて、インスタンスのプロパティと使用方法が変わります。この情報のうち、イメージと可用性ゾーンを除いた設定はインスタンスの作成後も変更できますが、一部のインスタンスタイプ (flavor) はインスタンスの作成後に変更できません。インスタンスタイプの変更の詳細については、[コンソール使用ガイドのインスタンスタイプ変更](./console-guide/#modify-flavor)を参照してください。

<a id="image"></a>
### イメージ { #image }

イメージはオペレーティングシステムを格納する仮想ディスクです。NHN Cloud は現在、Debian、Ubuntu、Rocky、および Windows をサポートしています。

すべてのイメージはインスタンスの仮想ハードウェア上で最適に実行されるように設定されており、NHN Cloud のセキュリティ検証を受けているため、安全に使用できます。イメージの詳細については、[イメージの概要](/Compute/Image/ja/overview/)を参照してください。

<a id="flavor"></a>
### インスタンスタイプ (Instance flavor) { #flavor }

NHN Cloud は、顧客の用途に合わせたさまざまなインスタンスタイプを提供します。運用するサービスまたはアプリケーションの特性に応じて、適切なタイプのインスタンスを作成できます。既に作成されたインスタンスのタイプは、ウェブコンソールで簡単に変更できます。

| タイプ    | 説明                                                                                                                                               |
| ------- |--------------------------------------------------------------------------------------------------------------------------------------------------|
| m2 | CPU とメモリをバランスよく設定したタイプです。サービスやアプリケーションのパフォーマンス要件が明確でない場合に使用します。                                                                               |
| c2 | CPU のパフォーマンスを高く設定したインスタンスタイプです。高性能な計算パフォーマンスが必要なウェブアプリケーションサーバーまたは分析システムに使用します。                                                                           |
| r2 | 他のリソースと比較してメモリの使用量が多い場合に使用できます。通常、メモリデータベースまたはキャッシュサーバーに使用します。                                                                               |
| t2 | コストが低いインスタンスです。ワークロードが高くないサーバーに使用します。                                                                                                          |
| u2 | 最も低コストのインスタンスです。ワークロードが高くないサーバーで使用します。<br>ローカルブロックストレージを使用するため、相対的に他のインスタンスよりも安定性が劣りますが、低コストで利用できます。<br>このタイプのインスタンスは I/O パフォーマンスを保証しません。 |
| x1 | 高性能 CPU とメモリをサポートするタイプです。高いパフォーマンスが必要なサービスやアプリケーションに使用します。                                                                                        |

<a id="availability-zone"></a>
### 可用性ゾーン (Availability zone) { #availability-zone }

NHN Cloud は物理ハードウェアの問題による障害に備えるため、システム全体を複数の可用性ゾーンに分割しています。この可用性ゾーンごとに、ストレージシステム、ネットワークスイッチ、ラック、および電源装置がすべて別々に構成されています。1 つの可用性ゾーン内で発生する障害は他の可用性ゾーンに影響を与えないため、サービス全体の可用性が高まります。インスタンスを複数の可用性ゾーンに分散して構築すれば、サービスの可用性をさらに高めることができます。

異なる可用性ゾーン間には、次のような特性があります。

- 複数の可用性ゾーンに分散して作成されたインスタンス同士はネットワーク通信が可能であり、このときに発生するネットワーク使用コストは課金されません。
- 同じ可用性ゾーン内に作成されたインスタンス間ではブロックストレージを共有できますが、異なる可用性ゾーン間ではブロックストレージを共有できません。
- 異なる可用性ゾーン間でフローティング IP を共有できます。1 つの可用性ゾーンで障害が発生した場合でも、フローティング IP を別の可用性ゾーンにすばやく移動して、ダウンタイムを最小化できます。

<a id="key-pair"></a>
### キーペア (Key-pair) { #key-pair }

キーペアは、公開キー基盤 ([PKI](https://ko.wikipedia.org/wiki/%EA%B3%B5%EA%B0%9C_%ED%82%A4_%EA%B8%B0%EB%B0%98_%EA%B5%AC%EC%A1%B0) (public key infrastructure)) に基づいた SSH 公開キーおよび秘密キーのペアです。NHN Cloud で作成されたインスタンスにアクセスするには、セキュリティが脆弱なキーボード入力方式のユーザー ID/パスワード認証の代わりに、キーペアを使用する必要があります。ユーザーはキーペアの秘密キーを使用してログイン情報をエンコードしてインスタンスに送信し、アクセス認証を受けた後、インスタンスに安全にアクセスできます。キーペアを使用したインスタンスのアクセス方法については、[インスタンスのアクセス方法](#how-to-access-instances)を参照してください。

キーペアはインスタンスを作成するとき、NHN Cloud コンソールで新規に作成することも、顧客が直接作成したキーペアを登録して使用することもできます。キーペア登録の方法については、[コンソールガイドのキーペアのインポート](./console-guide/#import-key-pairs-windows)を参照してください。

> [注意]
> キーペアを新規作成すると、キーペアの秘密キーをダウンロードします。秘密キーは再発行できないため、ダウンロードした秘密キーは安全なディスクや USB ドライブなどに安全に保管してください。秘密キーが外部に漏洩した場合、誰でも漏洩した秘密キーを使用して該当するインスタンスにアクセスできるため、慎重に管理する必要があります。

> [注記]
> キーペアはユーザーアカウントに割り当てられたリソースであるため、プロジェクトを削除しても削除されず、保持されます。

<a id="security-groups"></a>
### セキュリティグループ (Security groups) { #security-groups }

セキュリティグループはインスタンスに送信されるネットワークトラフィックを決定する仮想ファイアウォールです。セキュリティグループの詳細については、[VPC の概要](/Network/VPC/ja/overview/)を参照してください。

> [注記]
> デフォルトセキュリティグループは、外部から着信するインバウンド (in-bound) ネットワークトラフィックをすべて無視するように設定されています。SSH でインスタンスにアクセスするときは、インスタンスが属するセキュリティグループで SSH ポートを開くように設定してからインスタンスにアクセスします。

<a id="network"></a>
### ネットワーク { #network }

インスタンスが外部と通信するには、VPC で定義されたネットワークの少なくとも 1 つ以上に接続されている必要があります。ネットワークに接続されていないインスタンスにはアクセスできません。ネットワークを新規作成または変更するには、[VPC の概要](/Network/VPC/ja/overview/)を参照してください。

<a id="pricing"></a>
## 課金 { #pricing }

インスタンスの課金方法は次のとおりです。

* インスタンスは作成した時点から課金されます。
* インスタンスのルートブロックストレージは、インスタンスとは別にブロックストレージの課金基準で課金されます。
* インスタンスが停止されると、90 日間はホームページ料金基準の 90% 割引額が適用されます。停止状態が 90 日を超えた場合、停止状態を維持したまま通常料金に変換されます。
* 終了されたインスタンスは課金されません。

課金の詳細については、サービス別の[料金ページ](https://www.toast.com/kr/service/compute/instance#price)を参照してください。

<a id="how-to-access-instances"></a>
## インスタンスのアクセス方法 { #how-to-access-instances }

<a id="how-to-access-linux-instances"></a>
### Linux インスタンスのアクセス方法 { #how-to-access-linux-instances }

Linux インスタンスにアクセスするときは SSH クライアントを使用します。インスタンスのセキュリティグループで SSH アクセスポート (デフォルト 22) が開いていない場合、アクセスできません。SSH アクセスを許可する方法については、[VPC の概要](/Network/VPC/ja/overview/)を参照してください。インスタンスにフローティング IP が割り当てられていない場合、NHN Cloud の外部からアクセスできません。フローティング IP を割り当てる方法については、[VPC の概要](/Network/VPC/ja/overview/)を参照してください。

<a id="how-to-access-linux-instances-from-mac-or-linux-using-an-ssh-client"></a>
#### Mac または Linux の SSH クライアントから Linux インスタンスにアクセスする方法

Mac または Linux には、通常 SSH クライアントがデフォルトでインストールされています。SSH クライアントから以下のようにキーペアの秘密キーを使用してアクセスします。

Ubuntu インスタンス

	$ ssh -i my_private_key.pem ubuntu@<インスタンスの IP>

Debian インスタンス

	$ ssh -i my_private_key.pem debian@<インスタンスの IP>

Rocky インスタンス

	$ ssh -i my_private_key.pem rocky@<インスタンスの IP>

<a id="how-to-access-linux-instances-from-windows-using-putty-ssh-client"></a>
#### Windows の PuTTY SSH クライアントから Linux インスタンスにアクセスする方法

PuTTY SSH クライアントは、Windows で一般的に使用される SSH クライアントプログラムです。[PuTTY](https://www.chiark.greenend.org.uk/~sgtatham/putty/latest.html) または日本語パッチが適用された [iPuTTY](https://github.com/iPuTTY/iPuTTY/releases/tag/l0.70i) をインストールします。

Windows の PuTTY SSH クライアントから Linux インスタンスにアクセスするには、3 つの段階を経る必要があります。

* キーペアの秘密キーを PuTTY 用の秘密キーに変更
* PuTTY 用の秘密キーを PuTTY に登録
* PuTTY でインスタンスにアクセス

##### 1. キーペアの秘密キーを PuTTY 用の秘密キーに変更

PuTTY ではキーペアの秘密キーを PuTTY の秘密キー形式に変換して使用する必要があります。キー変換は PuTTY と一緒にインストールされる puttygen を使用します。

![image1](http://static.toastoven.net/prod_instance/putty001.png)

**PuTTY Key Generator** ダイアログの下部の**パラメータ**で、**生成するキーの種類**を **RSA** に選択し、**生成するキーのビット数**をデフォルト値の「2048」ビットで入力します。**操作**下の**秘密キーファイルの読み込み**の横の**読み込み**ボタンをクリックし、キーペアの秘密キーファイルを読み込みます。

![image2](http://static.toastoven.net/prod_instance/putty002.png)

**操作**下の**生成されたキーの保存**の横の**秘密キーの保存**ボタンをクリックして、PuTTY 用に変換されたキーペアの秘密キーを保存します。**キーパスフレーズ**を空白のままで秘密キーを保存すると、「**パスフレーズで保護されていないでこのキーを保存しますか？**」というメッセージが表示されます。変換された秘密キーをより安全に保存する場合は、パスフレーズを設定して保存します。

> [注意]
> インスタンスに自動的にログインするように設定するには、パスフレーズを使用しないでください。パスフレーズを使用する場合、ログイン時に秘密キーのパスワードを直接入力する必要があります。

##### 2. PuTTY 用の秘密キーを PuTTY に登録

このようにして作成された PuTTY 用の秘密キーは、2 つの方法で登録して使用できます。

* PuTTY で認証秘密キーファイルを登録して使用する方法
* pageant (PuTTY Authentication Agent) に認証秘密キーファイルを登録して使用する方法

**A. PuTTY で認証秘密キーファイルを登録して使用する方法**

PuTTY を実行し、左側の**カテゴリ**から**Connection > SSH > Auth** を選択します。右側の**認証パラメータ**下の**認証秘密キーファイル**に PuTTY 用の秘密キーを登録します。

![image3](http://static.toastoven.net/prod_instance/putty005.png)

秘密キーを登録した後、接続情報を保存しておくと、毎回秘密キーファイルを再度登録する必要がありません。接続情報を保存する方法については、以下のアクセス方法を参照してください。

**B. pageant (PuTTY Authentication Agent) に認証秘密キーファイルを登録して使用する方法**

PuTTY と一緒にインストールされる pageant を実行すると、以下の図のように Windows トレイにアイコンが表示されます。pageant アイコンを右クリックした後、**キーを追加**メニューをクリックして、PuTTY 用の秘密キーを追加します。

![image4](http://static.toastoven.net/prod_instance/putty006.png)

秘密キーが追加されたことを確認するには、**キーを表示**を選択します。キーが正常に追加された場合、以下の図のように追加されたキーが表示されます。

![image5](http://static.toastoven.net/prod_instance/putty008.png)

pageant は、一度実行されると Windows トレイに継続して残るため、インスタンスにアクセスするたびに再度実行する必要がありません。ただし、Windows を再起動した場合は再度実行する必要があります。

##### 3. PuTTY でインスタンスにアクセス

PuTTY 用に変換された秘密キーが正常に登録されたら、PuTTY を実行します。

![image6](http://static.toastoven.net/prod_instance/putty009.png)

基本接続情報の**ホスト名**は、次のように使用します。

Ubuntu

	ubuntu@<インスタンスの IP>

Debian

	debian@<インスタンスの IP>

Rocky

	rocky@<インスタンスの IP>

**ポート**は SSH デフォルトポート 22 に、**接続タイプ**は **SSH** に指定します。

すべての情報が正確な場合、セッションを保存します。**セッションの読み込み、保存、削除**で、保存されたセッション下のフィールドに保存するセッション名を入力し、**保存**ボタンをクリックしてセッションを保存します。セッションを保存しない場合、2-A で登録した秘密キー設定も保持されません。

これで**開く**をクリックすると、インスタンスにアクセスします。

<a id="how-to-access-windows-instances"></a>
### Windows インスタンスのアクセス方法 { #how-to-access-windows-instances }

Windows サーバーにアクセスするには、NHN Cloud コンソールでアクセスする Windows インスタンスを選択します。インスタンスの詳細画面の**接続情報**タブで**パスワード確認**ボタンをクリックして、Windows サーバーに設定されたパスワードを確認します。

**パスワード確認**で入力するキーペアの秘密キーはサーバーに送信されず、ブラウザーでパスワードを復号化する操作にのみ使用されます。

**パスワード確認**の横の**接続**ボタンをクリックしてリモートデスクトップアクセス設定が保存された .rdp ファイルを取得して実行すると、Windows サーバーにアクセスします。Windows サーバーのユーザー ID は `Administrator` で、パスワードは NHN Cloud コンソールで確認したパスワードを使用します。

<a id="how-to-connect-serial-console"></a>
### シリアルコンソールのアクセス方法 { #how-to-connect-serial-console }

ブート失敗、ネットワーク構成の問題など、SSH クライアントを使用できない状況でシリアルコンソールに接続してインスタンスにアクセスできます。

シリアルコンソール機能には次のような制限があります。

* インスタンスごとに 1 つのシリアルコンソール接続のみ可能であり、複数接続を試みた場合、正常に接続されない可能性があります。
* 個人がアップロードしたイメージから作成されたインスタンスおよびプライベートイメージから作成されたインスタンスは、シリアルコンソールのアクセスを保証しません。
* シリアルコンソール接続は最大 10 分間アクセス可能です。
* Windows インスタンスはシリアルコンソール機能をサポートしていません。
* 2026 年 1 月 27 日のデプロイ前に作成されたインスタンスは、**インスタンスの停止**後に**インスタンスの起動**が必要です。**インスタンスの再起動**機能では適用されません。

> [注意]
> シリアルコンソールでインスタンスにアクセスしてブートメソッドを変更する場合、ブート失敗の可能性があり、この結果についての責任はユーザーにあります。
> 一般的な状況では SSH クライアントのアクセス使用をお勧めします。

<a id="how-to-connect-serial-console-change-grub-bootloader-settings"></a>
#### GRUB ブートローダー設定の変更

2024 年 11 月 26 日のデプロイ前に作成されたインスタンスでブートローダーを操作するには、GRUB 設定が必要です。

GRUB 設定ファイルを編集します。

```
$ sudo vi /etc/default/grub.d/50-cloudimg-settings.cfg
GRUB_TIMEOUT=3
GRUB_TERMINAL="console serial"
GRUB_SERIAL_COMMAND="serial --speed=9600 --unit=0 --word=8 --parity=no --stop=1"
````

変更された設定を適用します。OS によって GRUB 設定の適用コマンドが異なる場合があります。

```
$ sudo update-grub
```
