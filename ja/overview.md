<a id="compute-instance-overview"></a>
## Compute > Instance > 概要 { #compute-instance-overview }

インスタンスは、仮想 CPU、メモリ、ルート ブロックストレージで構成される仮想サーバーです。このサーバーに顧客のサービスまたはアプリケーションをインストールし、NHN Cloud が提供する各種サービスと組み合わせて使用します。

<a id="components"></a>
## インスタンスの構成要素 { #components }

インスタンスを構成する要素は次のとおりです。

- **イメージ**: インスタンスのオペレーティングシステムを格納する仮想ディスク
- **タイプ** (flavor): インスタンスの仮想ハードウェアのパフォーマンス
- **可用性ゾーン** (AZ、availability zone): インスタンスが作成される物理的な場所
- **キーペア** (key-pair): インスタンスへのアクセス手段として使用されるキー
- **セキュリティグループ** (security groups): インスタンスのネットワークセキュリティ設定
- **ネットワーク**: インスタンスが接続される仮想ネットワーク

この情報に基づいて、インスタンスの属性と使用方法が決定されます。このうち、イメージと可用性ゾーンを除く設定はインスタンス作成後も変更できます。ただし、一部のインスタンスタイプ (flavor) はインスタンス作成後に変更できません。インスタンスタイプの変更についての詳細は、[コンソール使用ガイドのインスタンスタイプ変更](./console-guide/#modify-flavor)を参照してください。

<a id="image"></a>
### イメージ { #image }

イメージはオペレーティングシステムを格納する仮想ディスクです。NHN Cloud は現在、Debian、Ubuntu、Rocky、および Windows をサポートしています。

すべてのイメージはインスタンスの仮想ハードウェア上で最適に実行されるように設定されており、NHN Cloud のセキュリティ検証を受けているため、安全に使用できます。イメージについての詳細は、[イメージの概要](/Compute/Image/ja/overview/)を参照してください。

<a id="flavor"></a>
### インスタンスタイプ (Instance flavor) { #flavor }

NHN Cloud は、顧客の使用目的に合った各種インスタンスタイプを提供します。運用するサービスまたはアプリケーションの特性に応じて、適切なタイプのインスタンスを作成できます。既に作成されたインスタンスのタイプも、ウェブコンソールで簡単に変更できます。

| タイプ    | 説明                                                                                                                                               |
| ------- |--------------------------------------------------------------------------------------------------------------------------------------------------|
| m2 | CPU とメモリのバランスが取れたタイプです。サービスまたはアプリケーションのパフォーマンス要件が明確でない場合に使用します。                                                                               |
| c2 | CPU のパフォーマンスが高く設定されたインスタンスタイプです。高いコンピューティング性能が必要なウェブアプリケーションサーバーまたは分析システムで使用します。                                                                           |
| r2 | 他のリソースと比べてメモリの使用量が多い場合に使用できます。通常はメモリデータベースまたはキャッシュサーバーで使用します。                                                                               |
| t2 | コストが低いインスタンスです。ワークロードが低いサーバーで使用します。                                                                                                          |
| u2 | 最も低コストのインスタンスです。ワークロードが低いサーバーで使用します。<br>ローカルブロックストレージを使用するため、他のインスタンスと比べて相対的に安定性は低くなりますが、低価格で利用できます。<br>このタイプのインスタンスは I/O パフォーマンスを保証しません。 |
| x1 | 高性能の CPU とメモリをサポートするタイプです。高いパフォーマンスが必要なサービスまたはアプリケーションで使用します。                                                                                        |

<a id="availability-zone"></a>
### 可用性ゾーン (Availability zone) { #availability-zone }

NHN Cloud は、物理ハードウェアの問題による障害に備えるために、システム全体を複数の可用性ゾーンに分割しています。各可用性ゾーンでは、ストレージシステム、ネットワークスイッチ、ラック、電源装置がすべて個別に構成されています。1 つの可用性ゾーン内で発生した障害は、他の可用性ゾーンに影響を与えないため、サービス全体の可用性が向上します。インスタンスを複数の可用性ゾーンに分散して構築することで、サービスの可用性をさらに高めることができます。

異なる可用性ゾーン間には、次の特性があります。

- 複数の可用性ゾーンに分散して作成されたインスタンス間でネットワーク通信が可能であり、この際に発生するネットワーク使用料は課金されません。
- 同じ可用性ゾーン内に作成されたインスタンス間ではブロックストレージを共有できますが、異なる可用性ゾーン間ではブロックストレージを共有できません。
- 異なる可用性ゾーン間でフローティング IP を共有できます。1 つの可用性ゾーンで障害が発生した場合でも、フローティング IP を迅速に別の可用性ゾーンに移動して、障害時間を最小化できます。

<a id="key-pair"></a>
### キーペア (Key-pair) { #key-pair }

キーペアは、公開鍵基盤 ([PKI](https://ko.wikipedia.org/wiki/%EA%B3%B5%EA%B0%9C_%ED%82%A4_%EA%B8%B0%EB%B0%98_%EA%B5%AC%EC%A1%B0)、public key infrastructure) に基づいた SSH 公開鍵と秘密鍵のペアです。NHN Cloud で作成したインスタンスにアクセスするには、セキュリティに脆弱なキーボード入力方式のユーザー ID/パスワード認証の代わりに、キーペアを使用する必要があります。ユーザーはキーペアの秘密鍵を使用してログイン情報をエンコードしてインスタンスに送信し、アクセス認証を受けた後、安全にインスタンスにアクセスできます。キーペアを使用したインスタンスへのアクセス方法については、[インスタンスへのアクセス方法](#how-to-access-instances)を参照してください。

キーペアはインスタンス作成時に NHN Cloud コンソールで新規作成することも、顧客が直接作成したキーペアを登録して使用することもできます。キーペア登録方法については、[コンソールガイドのキーペアのインポート](./console-guide/#import-key-pairs-windows)を参照してください。

> [注意]
> キーペアを新規作成すると、キーペアの秘密鍵がダウンロードされます。秘密鍵は再発行できないため、ダウンロードした秘密鍵は安全なディスクまたは USB ドライブなどに適切に保管してください。秘密鍵が外部に漏洩した場合、誰でも漏洩した秘密鍵を使用してそのインスタンスにアクセスできるため、慎重に管理する必要があります。

> [注記]
> キーペアはユーザーアカウントに割り当てられたリソースであるため、プロジェクトを削除してもキーペアは削除されず、保持されます。

<a id="security-groups"></a>
### セキュリティグループ (Security groups) { #security-groups }

セキュリティグループは、インスタンスに送信されるネットワークトラフィックを決定する仮想ファイアウォールです。セキュリティグループについての詳細は、[VPC の概要](/Network/VPC/ja/overview/)を参照してください。

> [注記]
> デフォルトセキュリティグループは、外部からのインバウンド (in-bound) ネットワークトラフィックをすべて無視するように設定されています。SSH でインスタンスにアクセスする場合、インスタンスが属するセキュリティグループで SSH ポートを開くように設定した後、インスタンスにアクセスします。

<a id="network"></a>
### ネットワーク { #network }

インスタンスが外部と通信するには、VPC で定義されたネットワークのうち、少なくとも 1 つ以上に接続されている必要があります。ネットワークに接続されていないインスタンスにはアクセスできません。新しくネットワークを作成または変更するには、[VPC の概要](/Network/VPC/ja/overview/)を参照してください。

<a id="pricing"></a>
## 課金 { #pricing }

インスタンスの課金方法は次のとおりです。

* インスタンスは、作成した時点から課金されます。
* インスタンスのルートブロックストレージは、インスタンスとは別にブロックストレージの課金基準に従って課金されます。
* インスタンスが停止されている場合、90 日間はホームページの料金基準から 90% 割引された金額が適用されます。停止状態が 90 日を超えた場合、停止状態を保持したまま通常料金に変わります。
* 終了したインスタンスは課金されません。

課金についての詳細は、サービス別の [料金ページ](https://www.toast.com/kr/service/compute/instance#price)を参照してください。

<a id="how-to-access-instances"></a>
## インスタンスへのアクセス方法 { #how-to-access-instances }

<a id="how-to-access-linux-instances"></a>
### Linux インスタンスへのアクセス方法 { #how-to-access-linux-instances }

Linux インスタンスにアクセスするには、SSH クライアントを使用します。インスタンスのセキュリティグループで SSH アクセスポート (デフォルトは 22) が開かれていない場合、アクセスできません。SSH アクセスを許可する方法については、[VPC の概要](/Network/VPC/ja/overview/)を参照してください。インスタンスにフローティング IP が割り当てられていない場合、NHN Cloud の外部からアクセスすることはできません。フローティング IP を割り当てる方法については、[VPC の概要](/Network/VPC/ja/overview/)を参照してください。

<a id="how-to-access-linux-instances-from-mac-or-linux-using-an-ssh-client"></a>
#### Mac または Linux の SSH クライアントで Linux インスタンスにアクセスする方法

Mac または Linux では、通常、SSH クライアントがデフォルトでインストールされています。SSH クライアントでキーペアの秘密鍵を使用して、次のようにアクセスします。

Ubuntu インスタンス

	$ ssh -i my_private_key.pem ubuntu@<インスタンスの IP>

Debian インスタンス

	$ ssh -i my_private_key.pem debian@<インスタンスの IP>

Rocky インスタンス

	$ ssh -i my_private_key.pem rocky@<インスタンスの IP>

<a id="how-to-access-linux-instances-from-windows-using-putty-ssh-client"></a>
#### Windows の PuTTY SSH クライアントで Linux インスタンスにアクセスする方法

PuTTY SSH クライアントは、Windows で一般的に使用される SSH クライアントプログラムです。[PuTTY](https://www.chiark.greenend.org.uk/~sgtatham/putty/latest.html) または日本語パッチが適用された [iPuTTY](https://github.com/iPuTTY/iPuTTY/releases/tag/l0.70i) をインストールします。

Windows の PuTTY SSH クライアントで Linux インスタンスにアクセスするには、3 つのステップを実行する必要があります。

* キーペアの秘密鍵を PuTTY 用の秘密鍵に変換する
* PuTTY 用の秘密鍵を PuTTY に登録する
* PuTTY でインスタンスにアクセスする

##### 1. キーペアの秘密鍵を PuTTY 用の秘密鍵に変換

PuTTY では、キーペアの秘密鍵を PuTTY の秘密鍵形式に変換して使用する必要があります。キー変換は、PuTTY と一緒にインストールされる puttygen を使用します。

![画像 1](http://static.toastoven.net/prod_instance/putty001.png)

**PuTTY Key Generator** ダイアログの最下部にある **パラメータ** で、**生成するキーの種類** を **RSA** として選択し、**生成するキーのビット数** はデフォルト値の「2048」ビットを入力します。**操作** の下の **秘密鍵ファイルの読み込み** の横にある **読み込む** ボタンをクリックして、キーペアの秘密鍵ファイルを読み込みます。

![画像 2](http://static.toastoven.net/prod_instance/putty002.png)

**操作** の下の **生成されたキーを保存** の横にある **秘密鍵を保存** ボタンをクリックして、PuTTY 用に変換されたキーペアの秘密鍵を保存します。**キーパスフレーズ** を空白のままにして秘密鍵を保存すると、**パスフレーズなしでこのキーを保存してもよろしいですか？** というメッセージが表示されます。変換された秘密鍵をより安全に保存するには、パスフレーズを設定して保存します。

> [注意]
> インスタンスに自動的にログインするように設定するには、パスフレーズを使用しないでください。パスフレーズを使用すると、ログイン時に秘密鍵のパスワードを直接入力する必要があります。

##### 2. PuTTY 用の秘密鍵を PuTTY に登録

このように作成された PuTTY 用の秘密鍵は、2 つの方法で登録して使用できます。

* PuTTY で認証秘密鍵ファイルを登録して使用する方法
* pageant (PuTTY 認証エージェント) に認証秘密鍵ファイルを登録して使用する方法

**A. PuTTY で認証秘密鍵ファイルを登録して使用する方法**

PuTTY を実行して、左側の **カテゴリ** から **接続 > SSH > Auth** を選択します。右側の **認証パラメータ** の下の **認証秘密鍵ファイル** に PuTTY 用の秘密鍵を登録します。

![画像 3](http://static.toastoven.net/prod_instance/putty005.png)

秘密鍵を登録した後、アクセス情報を保存しておくと、毎回秘密鍵ファイルを再度登録する必要がなくなります。アクセス情報の保存方法については、以下のアクセス方法を参照してください。

**B. pageant (PuTTY 認証エージェント) に認証秘密鍵ファイルを登録して使用する方法**

PuTTY と一緒にインストールされる pageant を実行すると、次の図のように Windows トレイにアイコンが表示されます。pageant アイコンを右クリックし、**キーの追加** メニューをクリックして、PuTTY 用の秘密鍵を追加します。

![画像 4](http://static.toastoven.net/prod_instance/putty006.png)

秘密鍵が追加されたことを確認するには、**キーの表示** を選択します。キーが正常に追加されている場合、次の図のように追加されたキーが表示されます。

![画像 5](http://static.toastoven.net/prod_instance/putty008.png)

pageant は一度実行されると、Windows トレイに継続して表示されたままになるため、インスタンスにアクセスするたびに再度実行する必要がありません。ただし、Windows を再起動した場合は再度実行する必要があります。

##### 3. PuTTY でインスタンスにアクセス

PuTTY 用に変換された秘密鍵が正しく登録されたら、PuTTY を実行します。

![画像 6](http://static.toastoven.net/prod_instance/putty009.png)

基本的なアクセス情報の **ホスト名** は、次のように使用します。

Ubuntu

	ubuntu@<インスタンスの IP>

Debian

	debian@<インスタンスの IP>

Rocky

	rocky@<インスタンスの IP>

**ポート** は SSH のデフォルトポートである 22 に、**接続タイプ** は **SSH** に指定します。

すべての情報が正確な場合は、セッションを保存します。**読み込む、保存、保存されたセッションを削除** で、保存されたセクションの下にあるフィールドに保存するセッション名を入力し、**保存** ボタンをクリックしてセッションを保存します。セッションを保存しない場合、2 番目のステップで登録した秘密鍵の設定も保持されません。

これで **開く** をクリックするとインスタンスにアクセスします。

<a id="how-to-access-windows-instances"></a>
### Windows インスタンスへのアクセス方法 { #how-to-access-windows-instances }

Windows サーバーにアクセスするには、NHN Cloud コンソールでアクセスする Windows インスタンスを選択します。インスタンスの詳細画面の **アクセス情報** タブで **パスワード確認** ボタンをクリックして、Windows サーバーに設定されたパスワードを確認します。

**パスワード確認** で入力するキーペアの秘密鍵はサーバーに送信されず、ブラウザーでパスワードを復号化する処理にのみ使用されます。

**パスワード確認** の横にある **接続** ボタンをクリックして、リモートデスクトップアクセス設定が保存された .rdp ファイルをダウンロードして実行すると、Windows サーバーにアクセスします。Windows サーバーのユーザー ID は `Administrator` で、パスワードは NHN Cloud コンソールで確認したパスワードを使用します。

<a id="how-to-connect-serial-console"></a>
### シリアルコンソールへのアクセス方法 { #how-to-connect-serial-console }

ブート失敗やネットワーク構成の問題など、SSH クライアントを使用できない状況では、シリアルコンソールに接続してインスタンスにアクセスできます。

シリアルコンソール機能には、次の制限があります。

* インスタンスあたり 1 つのシリアルコンソール接続のみが可能で、複数接続を試みるとアクセスが正常に確立されない場合があります。
* ユーザーがアップロードしたイメージから作成されたインスタンスと個人イメージから作成されたインスタンスは、シリアルコンソールアクセスを保証しません。
* シリアルコンソール接続は最大 10 分間のアクセスが可能です。
* Windows インスタンスはシリアルコンソール機能をサポートしていません。
* 2026 年 1 月 27 日のデプロイ前に作成されたインスタンスは、**インスタンスの停止** 後に **インスタンスの起動** が必要です。**インスタンスの再起動** 機能では適用されません。

> [注意]
> シリアルコンソールでインスタンスにアクセスしてブート方法を変更する場合、ブートに失敗する可能性があります。その結果の責任はユーザーにあります。
> 通常の状況では、SSH クライアントアクセスの使用をお勧めします。

<a id="how-to-connect-serial-console-change-grub-bootloader-settings"></a>
#### GRUB ブートローダー設定の変更

2024 年 11 月 26 日のデプロイ前に作成されたインスタンスでブートローダーを操作するには、GRUB 設定が必要です。

GRUB 設定ファイルを編集します。

```
$ sudo vi /etc/default/grub.d/50-cloudimg-settings.cfg
GRUB_TIMEOUT=3
GRUB_TERMINAL="console serial"
GRUB_SERIAL_COMMAND="serial --speed=9600 --unit=0 --word=8 --parity=no --stop=1"
````

変更された設定を適用します。OS によって GRUB 設定の適用コマンドが異なる場合があります。

```
$ sudo update-grub
```
