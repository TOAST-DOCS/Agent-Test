<a id="compute-instance-overview"></a>
## Compute > Instance > 概要 { #compute-instance-overview }

インスタンスは仮想のCPU、メモリ、ルートブロックストレージで構成された仮想サーバーです。このサーバーに顧客のサービスやアプリケーションをインストールし、NHN Cloudが提供するさまざまなサービスを組み合わせて使用します。

<a id="components"></a>
## インスタンス構成要素 { #components }

インスタンスを構成する要素は次のとおりです。

- **イメージ**: インスタンスのオペレーティングシステムを含む仮想ディスク
- **Instance flavor**: インスタンスの仮想ハードウェアのパフォーマンス
- **Availability zone**: インスタンスが作成される物理的な位置
- **Key-pair**: インスタンスアクセスの手段として使用されるキー
- **Security groups**: インスタンスネットワークセキュリティ設定
- **ネットワーク**: インスタンスが接続される仮想ネットワーク

この情報に応じて、インスタンスの属性と使用方法が変わります。この情報のうち、イメージと可用性ゾーンを除いた設定は、インスタンス作成後にも変更できますが、一部のインスタンスタイプ(flavor)はインスタンス作成後に変更できません。インスタンスタイプの変更の詳細については、[コンソール使用ガイドのインスタンスタイプの変更](./console-guide/#modify-flavor)を参照してください。

<a id="image"></a>
### イメージ { #image }

イメージはオペレーティングシステムを含む仮想ディスクです。NHN Cloudは現在Debian、Ubuntu、RockyおよびWindowsをサポートしています。

すべてのイメージはインスタンスの仮想ハードウェアで最適に実行されるように構成されており、NHN Cloudのセキュリティ検証を受けているため、安全に使用できます。イメージの詳細については、[イメージ概要](/Compute/Image/ja/overview/)を参照してください。

<a id="flavor"></a>
### Instance flavor { #flavor }

NHN Cloudは顧客の用途に合わせてさまざまなインスタンスタイプを提供しています。実行するサービスまたはアプリケーションの特性に応じて、適切なタイプのインスタンスを作成できます。すでに作成されたインスタンスのタイプもWebコンソールから簡単に変更できます。

| タイプ    | 説明                                                                                                                                               |
| ------- |--------------------------------------------------------------------------------------------------------------------------------------------------|
| m2 | CPUとメモリをバランスよく構成したタイプです。サービスまたはアプリケーションのパフォーマンス要件が明確でない場合に使用します。                                                                               |
| c2 | CPUのパフォーマンスを高く設定したインスタンスタイプです。高性能な計算パフォーマンスが必要なWebアプリケーションサーバーまたは分析システムで使用します。                                                                           |
| r2 | 他のリソースと比較してメモリの使用量が多い場合に使用できます。通常、インメモリデータベースまたはキャッシュサーバーで使用します。                                                                               |
| t2 | コストが低いインスタンスです。ワークロードが低いサーバーで使用します。                                                                                                          |
| u2 | 最も低価格のインスタンスです。ワークロードが低いサーバーで使用します。<br>ローカルブロックストレージを使用するため、相対的に他のインスタンスより安定性は劣りますが、低価格で利用できます。<br>このタイプのインスタンスはI/Oパフォーマンスを保証しません。 |
| x1 | 高仕様のCPUとメモリをサポートするタイプです。高パフォーマンスが必要なサービスまたはアプリケーションで使用します。                                                                                        |

<a id="availability-zone"></a>
### Availability zone { #availability-zone }

NHN Cloudは物理ハードウェアの問題による障害に備えるため、システム全体を複数の可用性ゾーンに分割しています。この可用性ゾーン別に、ストレージシステム、ネットワークスイッチ、ラック、電源装置がすべて個別に構成されています。1つの可用性ゾーン内で発生した障害は他の可用性ゾーンに影響を与えないため、サービス全体の可用性が向上します。インスタンスを複数の可用性ゾーンに分散して構築すれば、サービスの可用性をさらに向上させることができます。

異なる可用性ゾーン間には、次のような特性があります。

- 複数の可用性ゾーンに分散して作成されたインスタンス間ではネットワーク通信が可能であり、このときに発生するネットワーク使用料は課金されません。
- 同じ可用性ゾーンに作成されたインスタンス間ではブロックストレージを共有できますが、異なる可用性ゾーン間ではブロックストレージを共有できません。
- 異なる可用性ゾーン間でフローティングIPを共有できます。1つの可用性ゾーンに障害が発生した場合でも、フローティングIPを別の可用性ゾーンに迅速に移動することで、障害時間を最小化できます。

<a id="key-pair"></a>
### Key-pair { #key-pair }

キーペアは公開鍵基盤([PKI](https://ja.wikipedia.org/wiki/%E5%85%AC%E9%96%8B%E9%8D%B5%E5%9F%BA%E7%9B%A4), public key infrastructure)に基づくSSH公開鍵と秘密鍵のペアです。NHN Cloudで作成したインスタンスにアクセスするには、セキュリティが脆弱なキーボード入力方式のユーザーID/パスワード認証の代わりにキーペアを使用する必要があります。ユーザーはキーペアの秘密鍵を使用してログイン情報をエンコードしてインスタンスに送信し、アクセス認証を受けた後、安全にインスタンスにアクセスできます。キーペアを使用したインスタンスアクセス方法については、[インスタンスアクセス方法](#how-to-access-instances)を参照してください。

キーペアはインスタンスを作成するときにNHN Cloudコンソールで新規作成することもでき、顧客が直接作成したキーペアを登録して使用することもできます。キーペア登録方法については、[コンソールガイドのキーペアをインポート](./console-guide/#import-key-pairs-windows)を参照してください。

> [注意]
> キーペアを新規作成するとキーペアの秘密鍵がダウンロードされます。秘密鍵は再度発行できないため、ダウンロードした秘密鍵は安全なディスクやUSBドライブなどに適切に保管してください。秘密鍵が外部に漏出した場合、誰もが漏出した秘密鍵を使用して該当インスタンスにアクセスできるため、慎重に管理する必要があります。

> [注記]
> キーペアはユーザーアカウントに割り当てられたリソースであるため、プロジェクトを削除してもキーペアは削除されず、保持されます。

<a id="security-groups"></a>
### Security groups { #security-groups }

セキュリティグループはインスタンスに配信されるネットワークトラフィックを決定する仮想ファイアウォールです。セキュリティグループの詳細については、[VPC概要](/Network/VPC/ja/overview/)を参照してください。

> [注記]
> デフォルトセキュリティグループは外部から入ってくるインバウンド(in-bound)ネットワークトラフィックをすべて無視するように設定されています。SSHでインスタンスにアクセスするときは、インスタンスが属するセキュリティグループでSSHポートを開くように設定した後でインスタンスにアクセスします。

<a id="network"></a>
### ネットワーク { #network }

インスタンスが外部と通信するには、VPCで定義されたネットワークのうち、少なくとも1つ以上に接続されている必要があります。ネットワークに接続されていないインスタンスにはアクセスできません。ネットワークを新規作成または変更するには、[VPC概要](/Network/VPC/ja/overview/)を参照してください。

<a id="pricing"></a>
## 課金 { #pricing }

インスタンスの課金方式は次のとおりです。

* インスタンスは作成された時点から課金されます。
* インスタンスルートブロックストレージはインスタンスとは別にブロックストレージの課金基準によって課金されます。
* インスタンスが停止すると、90日間はホームページレート基準で90%割引された金額が適用されます。停止状態が90日を超えると、停止状態を維持しながら通常料金に切り替わります。
* 終了したインスタンスは課金されません。

課金の詳細については、サービス別の[料金ページ](https://www.toast.com/kr/service/compute/instance#price)を参照してください。

<a id="how-to-access-instances"></a>
## インスタンスアクセス方法 { #how-to-access-instances }

<a id="how-to-access-linux-instances"></a>
### Linux インスタンスアクセス方法 { #how-to-access-linux-instances }

Linux インスタンスにアクセスするときはSSHクライアントを使用します。インスタンスのセキュリティグループでSSHアクセスポート(デフォルト22)が開かれていない場合、アクセスできません。SSHアクセスを許可する方法については、[VPC概要](/Network/VPC/ja/overview/)を参照してください。インスタンスにフローティングIPが割り当てられていない場合、NHN Cloud外部からはアクセスできません。フローティングIPを割り当てる方法については、[VPC概要](/Network/VPC/ja/overview/)を参照してください。

<a id="how-to-access-linux-instances-from-mac-or-linux-using-an-ssh-client"></a>
#### MacまたはLinuxのSSHクライアントでLinuxインスタンスにアクセスする方法

MacやLinuxには通常、SSHクライアントがデフォルトでインストールされています。SSHクライアントで次のようにキーペアの秘密鍵を使用してアクセスします。

Ubuntuインスタンス

	$ ssh -i my_private_key.pem ubuntu@<インスタンスのIP>

Debianインスタンス

	$ ssh -i my_private_key.pem debian@<インスタンスのIP>

Rockyインスタンス

	$ ssh -i my_private_key.pem rocky@<インスタンスのIP>

<a id="how-to-access-linux-instances-from-windows-using-putty-ssh-client"></a>
#### WindowsのPuTTY SSHクライアントでLinuxインスタンスにアクセスする方法

PuTTY SSHクライアントはWindowsで広く使用されているSSHクライアントプログラムです。[PuTTY](https://www.chiark.greenend.org.uk/~sgtatham/putty/latest.html)または韓国語パッチが適用された[iPuTTY](https://github.com/iPuTTY/iPuTTY/releases/tag/l0.70i)をインストールします。

WindowsのPuTTY SSHクライアントでLinuxインスタンスにアクセスするには、3つのステップを実行する必要があります。

* キーペアの秘密鍵をPuTTY用秘密鍵に変更
* PuTTY用秘密鍵をPuTTYに登録
* PuTTYでインスタンスにアクセス

##### 1. キーペアの秘密鍵をPuTTY用秘密鍵に変更

PuTTYではキーペア秘密鍵をPuTTYの秘密鍵形式に変換して使用する必要があります。キー変換はPuTTYと一緒にインストールされるputtygenを使用します。

![イメージ1](http://static.toastoven.net/prod_instance/putty001.png)

**PuTTY Key Generator**ダイアログの一番下の**パラメーター**で、**生成するキーの種類**を**RSA**に選択し、**生成するキーのビット**はデフォルト値の「2048」ビットで入力します。**操作**の下の**秘密鍵ファイルの読み込み**の横の**読み込み**ボタンをクリックし、キーペアの秘密鍵ファイルを読み込みます。

![イメージ2](http://static.toastoven.net/prod_instance/putty002.png)

**操作**の下の**生成されたキーを保存**の横の**秘密鍵を保存**ボタンをクリックして、PuTTY用に変換されたキーペア秘密鍵を保存します。**キーパスフレーズ**を空白にして秘密鍵を保存すると、「**パスフレーズなしでこのキーを保存してもよろしいですか?**」というメッセージが表示されます。変換された秘密鍵をより安全に保存する場合は、パスフレーズを設定して保存します。

> [注意]
> インスタンスに自動的にログインするように設定するにはパスフレーズを使用しないでください。パスフレーズを使用すると、ログインするときに秘密鍵のパスワードを直接入力する必要があります。

##### 2. PuTTY用秘密鍵をPuTTYに登録

このように作成されたPuTTY用秘密鍵は2つの方法で登録して使用できます。

* PuTTYで認証秘密鍵ファイルを登録して使用する方法
* pageant(PuTTY認証エージェント)に認証秘密鍵ファイルを登録して使用する方法

**A. PuTTYで認証秘密鍵ファイルを登録して使用する方法**

PuTTYを実行し、左の**カテゴリ**で**接続 > SSH > Auth**を選択します。右の**認証パラメーター**の下の**認証秘密鍵ファイル**にPuTTY用秘密鍵を登録します。

![イメージ3](http://static.toastoven.net/prod_instance/putty005.png)

秘密鍵を登録した後、接続情報を保存しておくと、毎回秘密鍵ファイルを再度登録する必要がなくなります。接続情報を保存する方法については、下記の接続方法を参照してください。

**B. pageant(PuTTY認証エージェント)に認証秘密鍵ファイルを登録して使用する方法**

PuTTYと一緒にインストールされるpageantを実行すると、以下の図のようにWindowsトレイにアイコンが表示されます。pageantアイコンを右クリックした後、**キーを追加**メニューをクリックしてPuTTY用秘密鍵を追加します。

![イメージ4](http://static.toastoven.net/prod_instance/putty006.png)

秘密鍵が追加されたことを確認するには、**キーの表示**を選択します。キーが正常に追加されている場合、以下の図のように追加されたキーが表示されます。

![イメージ5](http://static.toastoven.net/prod_instance/putty008.png)

pageantは一度実行されると、Windowsトレイに継続的に残っている状態で実行されるため、インスタンスにアクセスするたびに再度実行する必要がありません。ただし、Windowsを再起動した場合には再度実行する必要があります。

##### 3. PuTTYでインスタンスにアクセス

PuTTY用に変換された秘密鍵が正常に登録されている場合、PuTTYを実行します。

![イメージ6](http://static.toastoven.net/prod_instance/putty009.png)

基本接続情報の**ホスト名**は次のように使用します。

Ubuntu

	ubuntu@<インスタンスのIP>

Debian

	debian@<インスタンスのIP>

Rocky

	rocky@<インスタンスのIP>

**ポート**はSSHデフォルトポートの22、**接続タイプ**は**SSH**に指定します。

すべての情報が正確である場合、セッションを保存します。**読み込み、保存、保存されたセッションの削除**で、保存されたセッションの下のフィールドに保存するセッション名を入力し、**保存**ボタンをクリックしてセッションを保存します。セッションを保存しない場合、2-Aで登録した秘密鍵設定も保持されません。

これで**開く**をクリックするとインスタンスにアクセスします。

<a id="how-to-access-windows-instances"></a>
### Windows インスタンスアクセス方法 { #how-to-access-windows-instances }

Windowsサーバーにアクセスするには、NHN Cloudコンソールでアクセスする対象のWindowsインスタンスを選択します。インスタンス詳細画面の**アクセス情報**タブで**パスワード確認**ボタンをクリックして、Windowsサーバーに設定されているパスワードを確認します。

**パスワード確認**で入力するキーペアの秘密鍵はサーバーに送信されず、ブラウザでパスワードを復号化するための処理にのみ使用されます。

**パスワード確認**の横の**接続**ボタンをクリックしてリモートデスクトップアクセス設定が保存された.rdpファイルを取得して実行すると、Windowsサーバーにアクセスします。WindowsサーバーのユーザーIDは`Administrator`であり、パスワードはNHN Cloudコンソールで確認したパスワードを使用します。

<a id="how-to-connect-serial-console"></a>
### シリアルコンソールアクセス方法 { #how-to-connect-serial-console }

ブート失敗やネットワーク構成の問題など、SSHクライアントを使用できない状況でシリアルコンソールに接続してインスタンスにアクセスできます。

シリアルコンソール機能には、次のような制限事項があります。

* インスタンスあたり1つのシリアルコンソール接続のみが可能であり、複数のアクセス試行時に正常に接続できない場合があります。
* ユーザーがアップロードしたイメージから作成されたインスタンスおよびプライベートイメージから作成されたインスタンスは、シリアルコンソールアクセスを保証しません。
* シリアルコンソール接続は最大10分間アクセス可能です。
* Windowsインスタンスはシリアルコンソール機能をサポートしていません。
* 2026年1月27日デプロイ前に作成されたインスタンスは、**インスタンス停止**の後に**インスタンス起動**が必要です。**インスタンス再起動**機能では適用されません。

> [注意]
> シリアルコンソールでインスタンスにアクセスしてブート方法を変更する場合、ブートに失敗する可能性があり、その結果に対する責任はユーザーにあります。
> 通常の状況ではSSHクライアントアクセスを使用することをお勧めします。

<a id="how-to-connect-serial-console-change-grub-bootloader-settings"></a>
#### GRUBブートローダー設定を変更

2024年11月26日デプロイ前に作成されたインスタンスでブートローダーを操作するにはGRUB設定が必要です。

GRUBの設定ファイルを修正します。

```
$ sudo vi /etc/default/grub.d/50-cloudimg-settings.cfg
GRUB_TIMEOUT=3
GRUB_TERMINAL="console serial"
GRUB_SERIAL_COMMAND="serial --speed=9600 --unit=0 --word=8 --parity=no --stop=1"
````

変更された設定を適用します。OSによってGRUB設定の適用コマンドが異なる場合があります。

```
$ sudo update-grub
```
