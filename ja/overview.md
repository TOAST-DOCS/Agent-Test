## Compute > Instance > 概要

インスタンスは、仮想CPU、メモリ、ルートブロックストレージで構成される仮想サーバーです。このサーバーに顧客のサービスやアプリケーションをインストールし、NHN Cloudが提供するさまざまなサービスと組み合わせて使用します。

<a id="components"></a>
## インスタンス構成要素

インスタンスを構成する要素は次のとおりです。

- **イメージ**: インスタンスのオペレーティングシステムを含む仮想ディスク
- **タイプ(flavor)**: インスタンスの仮想ハードウェアのパフォーマンス
- **Availability Zone**: インスタンスが作成される物理的な位置
- **キーペア**: インスタンスアクセスの手段として使用されるキー
- **Security Groups**: インスタンスネットワークセキュリティ設定
- **ネットワーク**: インスタンスが接続される仮想ネットワーク

この情報に応じてインスタンスの属性と使用方法が変わります。この情報のうち、イメージと可用性ゾーンを除く設定はインスタンス作成後も変更できますが、一部のインスタンスタイプ(flavor)はインスタンス作成後に変更できません。インスタンスタイプの変更の詳細は、[コンソール使用ガイドのインスタンスタイプ変更](./console-guide/#modify-flavor)を参照してください。

<a id="image"></a>
### イメージ

イメージはオペレーティングシステムを含む仮想ディスクです。NHN Cloudは現在Debian、Ubuntu、Rocky、およびWindowsをサポートしています。

すべてのイメージはインスタンスの仮想ハードウェアで最適に実行されるように設定されており、NHN Cloudのセキュリティ検証を通過しているため、安全に使用できます。イメージの詳細は、[イメージ概要](/Compute/Image/ja/overview/)を参照してください。

<a id="flavor"></a>
### インスタンスタイプ(Instance flavor)

NHN Cloudは、顧客の用途に合わせたさまざまなインスタンスタイプを提供しています。運用するサービスまたはアプリケーションの特性に応じて、適切なタイプのインスタンスを作成できます。すでに作成されたインスタンスのタイプもWebコンソールから簡単に変更できます。

| タイプ | 説明 |
| --- | --- |
| m2 | CPUとメモリのバランスが取れたタイプです。サービスまたはアプリケーションのパフォーマンス要件が明確でない場合に使用します。 |
| c2 | CPUのパフォーマンスが高く設定されたインスタンスタイプです。高いパフォーマンスの計算が必要なWebアプリケーションサーバーまたは分析システムに使用します。 |
| r2 | 他のリソースと比較してメモリの使用量が多い場合に使用できます。通常、メモリデータベースまたはキャッシュサーバーに使用します。 |
| t2 | コストが低いインスタンスです。ワークロードが高くないサーバーに使用します。 |
| u2 | 最も低コストのインスタンスです。ワークロードが高くないサーバーで使用します。<br>ローカルブロックストレージを使用しているため、他のインスタンスと比べて相対的に安定性は劣りますが、低コストで利用できます。<br>このタイプのインスタンスはI/Oパフォーマンスを保証しません。 |
| x1 | 高いスペックのCPUとメモリをサポートするタイプです。高いパフォーマンスが必要なサービスまたはアプリケーションに使用します。 |

<a id="availability-zone"></a>
### Availability Zone

NHN Cloudは、物理ハードウェア障害に対応するために、システム全体を複数の可用性ゾーンに分割しています。この可用性ゾーンごとに、ストレージシステム、ネットワークスイッチ、ラック、および電源装置がすべて個別に構成されています。一つの可用性ゾーン内で発生する障害は、他の可用性ゾーンに影響を与えないため、サービス全体の可用性が向上します。インスタンスを複数の可用性ゾーンに分散して構築すれば、サービスの可用性をさらに高めることができます。

異なる可用性ゾーン間には、次の特性があります。

- 複数の可用性ゾーンに分散して作成されたインスタンス間でネットワーク通信が可能であり、このときのネットワーク使用料は請求されません。
- 同じ可用性ゾーンに作成されたインスタンス間でブロックストレージを共有できますが、異なる可用性ゾーン間ではブロックストレージを共有できません。
- 異なる可用性ゾーン間でフローティングIPを共有できます。一つの可用性ゾーンに障害が発生した場合でも、フローティングIPを別の可用性ゾーンにすばやく移動して、ダウンタイムを最小化できます。

<a id="key-pair"></a>
### キーペア(Key-pair)

キーペアは、公開鍵基盤([PKI](https://ja.wikipedia.org/wiki/%E5%85%AC%E9%96%8B%E9%8D%B5%E5%9F%BA%E7%9B%A4), public key infrastructure)に基づくSSH公開鍵と秘密鍵のペアです。NHN Cloudで作成したインスタンスにアクセスするには、セキュリティ上脆弱なキーボード入力方式のID/パスワード認証の代わりにキーペアを使用する必要があります。ユーザーはキーペアの秘密鍵を使用してログイン情報をエンコードしてインスタンスに送信し、アクセス認証を受けた後、安全にインスタンスにアクセスできます。キーペアを使用したインスタンスアクセス方法は、[インスタンスアクセス方法](#how-to-access-instances)を参照してください。

キーペアはインスタンス作成時にNHN Cloudコンソールで新規作成することも、顧客が直接作成したキーペアを登録して使用することもできます。キーペア登録方法は、[コンソールガイドのキーペアのインポート](./console-guide/#import-key-pairs-windows)を参照してください。

> [注意]
> キーペアを新規作成すると、キーペアの秘密鍵をダウンロードします。秘密鍵は再発行できないため、ダウンロードした秘密鍵は安全なディスクやUSBドライブなどに保管してください。秘密鍵が外部に漏洩すると、誰でも漏洩した秘密鍵を使用してそのインスタンスにアクセスできるため、慎重に管理する必要があります。

> [参考]
> キーペアはユーザーアカウントに割り当てられたリソースのため、プロジェクトを削除してもキーペアは削除されず、保持されます。

<a id="security-groups"></a>
### Security Groups

Security Groupはインスタンスに配信されるネットワークトラフィックを決定する仮想ファイアウォールです。Security Groupの詳細は、[VPC概要](/Network/VPC/ja/overview/)を参照してください。

> [参考]
> デフォルトセキュリティグループは、外部からのインバウンド(in-bound)ネットワークトラフィックをすべて無視するように設定されています。SSHでインスタンスにアクセスする場合は、インスタンスが属するセキュリティグループでSSHポートを開くように設定してからインスタンスにアクセスしてください。

<a id="network"></a>
### ネットワーク

インスタンスが外部と通信するには、VPCで定義されたネットワークのうち、少なくとも1つ以上に接続されている必要があります。ネットワークに接続されていないインスタンスにはアクセスできません。ネットワークを新規作成または変更するには、[VPC概要](/Network/VPC/ja/overview/)を参照してください。

<a id="pricing"></a>
## 課金

インスタンスの課金方法は次のとおりです。

* インスタンスは作成時から課金されます。
* インスタンスのルートブロックストレージはインスタンスとは別に、ブロックストレージ課金基準で課金されます。
* インスタンスが停止された場合、90日間はホームページ料金基準により90%割引された金額が適用されます。停止状態が90日を超える場合、停止状態を維持しながら通常料金に変換されます。
* 終了されたインスタンスは課金されません。

課金の詳細については、サービス別[料金ページ](https://www.toast.com/kr/service/compute/instance#price)を参照してください。

<a id="how-to-access-instances"></a>
## インスタンスアクセス方法

<a id="how-to-access-linux-instances"></a>
### Linuxインスタンスへのアクセス方法

Linuxインスタンスにアクセスする場合は、SSHクライアントを使用します。インスタンスのセキュリティグループでSSHアクセスポート(デフォルト値22)が開いていない場合、アクセスできません。SSHアクセスを許可する方法については、[VPC概要](/Network/VPC/ja/overview/)を参照してください。インスタンスにフローティングIPが割り当てられていない場合、NHN Cloud外からアクセスできません。フローティングIPを割り当てる方法については、[VPC概要](/Network/VPC/ja/overview/)を参照してください。

#### MacまたはLinuxのSSHクライアントでLinuxインスタンスにアクセスする方法

MacまたはLinuxには、通常SSHクライアントがデフォルトでインストールされています。SSHクライアントから次のようにキーペアの秘密鍵を使用してアクセスします。

Ubuntuインスタンス

	$ ssh -i my_private_key.pem ubuntu@<インスタンスのIP>

Debianインスタンス

	$ ssh -i my_private_key.pem debian@<インスタンスのIP>

Rockyインスタンス

	$ ssh -i my_private_key.pem rocky@<インスタンスのIP>

#### WindowsからPuTTY SSHクライアントでLinuxインスタンスにアクセスする方法

PuTTY SSHクライアントはWindowsで広く使用されているSSHクライアントプログラムです。[PuTTY](https://www.chiark.greenend.org.uk/~sgtatham/putty/latest.html)または日本語パッチが適用された[iPuTTY](https://github.com/iPuTTY/iPuTTY/releases/tag/l0.70i)をインストールします。

WindowsからPuTTY SSHクライアントでLinuxインスタンスにアクセスするには、3つのステップを実行します。

* キーペアの秘密鍵をPuTTY用秘密鍵に変更する
* PuTTY用秘密鍵をPuTTYに登録する
* PuTTYでインスタンスにアクセスする

##### 1. キーペアの秘密鍵をPuTTY用秘密鍵に変更する

PuTTYではキーペア秘密鍵をPuTTYの秘密鍵形式に変更して使用する必要があります。キー変換はPuTTYと共にインストールされるputtygen を使用します。

![Image1](http://static.toastoven.net/prod_instance/putty001.png)

**PuTTY Key Generator**ダイアログボックスの一番下の**パラメータ**の**生成するキータイプ**を**RSA**に選択し、**生成するキーのビット数**はデフォルト値の「2048」ビットを入力します。**操作**の下の**秘密鍵ファイルの読み込み**の隣の**読み込み**ボタンをクリックし、キーペアの秘密鍵ファイルを読み込みます。

![Image2](http://static.toastoven.net/prod_instance/putty002.png)

**操作**の下の**生成されたキーの保存**の隣の**秘密鍵を保存**ボタンをクリックして、PuTTY用に変換されたキーペア秘密鍵を保存します。**キーパスフレーズ**を空欄のままにして秘密鍵を保存すると、「パスフレーズで保護されていないままこのキーを保存しますか?」というメッセージが表示されます。変換された秘密鍵をより安全に保存するには、パスフレーズを設定して保存します。

> [注意]
> インスタンスに自動的にログインするように設定するには、パスフレーズを使用しないようにしてください。パスフレーズを使用する場合は、ログイン時に秘密鍵のパスワードを直接入力する必要があります。

##### 2. PuTTY用秘密鍵をPuTTYに登録する

このようにして作成されたPuTTY用秘密鍵は2つの方法で登録して使用できます。

* PuTTYで認証秘密鍵ファイルを登録して使用する方法
* pageant(PuTTY認証エージェント)に認証秘密鍵ファイルを登録して使用する方法

**A. PuTTYで認証秘密鍵ファイルを登録して使用する方法**

PuTTYを実行し、左側の**カテゴリ**で**接続 > SSH > Auth**を選択します。右側の**認証パラメータ**の下の**認証秘密鍵ファイル**にPuTTY用秘密鍵を登録します。

![Image3](http://static.toastoven.net/prod_instance/putty005.png)

秘密鍵を登録した後、アクセス情報を保存すれば、以降秘密鍵ファイルを再度登録する必要がありません。アクセス情報を保存する方法は、以下のアクセス方法を参照してください。

**B. pageant(PuTTY認証エージェント)に認証秘密鍵ファイルを登録して使用する方法**

PuTTYと共にインストールされるpageantを実行すると、以下の図のようにWindowsトレイにアイコンが表示されます。pageantアイコンを右クリックした後、**キーを追加**メニューをクリックしてPuTTY用秘密鍵を追加します。

![Image4](http://static.toastoven.net/prod_instance/putty006.png)

秘密鍵が追加されたかを確認するには、**キーを表示**を選択します。キーが正常に追加されている場合は、以下の図のように追加されたキーが表示されます。

![Image5](http://static.toastoven.net/prod_instance/putty008.png)

pageantは一度実行されると、Windowsトレイに継続して実行されるため、インスタンスにアクセスするたびに再度実行する必要がありません。ただし、Windowsを再起動した場合は、再度実行する必要があります。

##### 3. PuTTYでインスタンスにアクセスする

PuTTY用に変換された秘密鍵が正常に登録されている場合、PuTTYを実行します。

![Image6](http://static.toastoven.net/prod_instance/putty009.png)

基本的なアクセス情報の**ホスト名**は次のように使用します。

Ubuntu

	ubuntu@<インスタンスのIP>

Debian

	debian@<インスタンスのIP>

Rocky

	rocky@<インスタンスのIP>

**ポート**はSSHのデフォルトポートである22、**接続タイプ**は**SSH**に指定します。

すべての情報が正確である場合、セッションを保存します。**読み込み、保存、保存されたセッションの削除**で保存されたセッションの下のフィールドに保存するセッション名を入力し、**保存**ボタンをクリックしてセッションを保存します。セッションを保存しない場合は、2-Aで登録した秘密鍵設定も保持されません。

これで**開く**をクリックするとインスタンスにアクセスします。

<a id="how-to-access-windows-instances"></a>
### Windowsインスタンスへのアクセス方法

Windowsサーバーにアクセスするには、NHN CloudコンソールでアクセスするWindowsインスタンスを選択します。インスタンス詳細画面の**アクセス情報**タブで**パスワード確認**ボタンをクリックして、Windowsサーバーに設定されたパスワードを確認します。

**パスワード確認**で入力するキーペアの秘密鍵はサーバーに送信されず、ブラウザーでパスワードを復号化するにのみ使用されます。

**パスワード確認**の隣の**接続**ボタンをクリックしてリモートデスクトップアクセス設定が保存された.rdpファイルを受け取って実行すると、Windowsサーバーにアクセスします。WindowsサーバーのユーザーIDは`Administrator`であり、パスワードはNHN Cloudコンソールで確認したパスワードを使用します。

### シリアルコンソールアクセス方法

ブート失敗やネットワーク構成問題など、SSHクライアントが使用できない状況でシリアルコンソールに接続してインスタンスにアクセスできます。

シリアルコンソール機能には、次の制限事項があります。

* インスタンスあたり1つのシリアルコンソール接続のみ可能であり、複数接続の試行時には正常に接続されない可能性があります。
* ユーザーがアップロードしたイメージで作成したインスタンスおよびプライベートイメージで作成したインスタンスは、シリアルコンソールアクセスを保証しません。
* シリアルコンソール接続は最大10分間アクセス可能です。
* Windowsインスタンスはシリアルコンソール機能をサポートしていません。
* 2026年1月27日のデプロイ以前に作成されたインスタンスは、**インスタンスの停止**の後に**インスタンスの開始**が必要です。**インスタンスの再起動**機能では適用されません。

> [注意]
> シリアルコンソールでインスタンスにアクセスしてブート方法を変更する際には、ブートに失敗する可能性があり、その結果についての責任はユーザーにあります。
> 通常の状況ではSSHクライアントアクセスの使用をお勧めします。

#### GRUB ブートローダー設定の変更

2024年11月26日のデプロイ以前に作成されたインスタンスでブートローダーを操作するにはGRUB設定が必要です。

GRUB設定ファイルを編集します。

```
$ sudo vi /etc/default/grub.d/50-cloudimg-settings.cfg
GRUB_TIMEOUT=3
GRUB_TERMINAL="console serial"
GRUB_SERIAL_COMMAND="serial --speed=9600 --unit=0 --word=8 --parity=no --stop=1"
```

変更された設定を適用します。OSによってGRUB設定適用コマンドが異なる場合があります。

```
$ sudo update-grub
```
