<a id="compute-instance-overview"></a>
## Compute > Instance > 概要 { #compute-instance-overview }

インスタンスは、仮想の CPU、メモリ、ルートブロックストレージで構成された仮想サーバーです。このサーバーにお客様のサービスやアプリケーションをインストールし、NHN Cloud が提供するさまざまなサービスを組み合わせて利用します。インスタンスは数分で作成でき、必要に応じていつでも拡張または縮小できます。

<a id="components"></a>
## インスタンス構成要素の概要 { #components }

インスタンスを構成する要素は次のとおりです。

- **イメージ**: インスタンスのオペレーティングシステムを格納した仮想ディスク
- **タイプ** (flavor): インスタンスの仮想ハードウェア性能
- **Availability Zone** (AZ、availability zone): インスタンスが作成される物理的な場所
- **キーペア** (key-pair): インスタンスへのアクセスに使用するキー
- **セキュリティグループ** (security groups): インスタンスのネットワークセキュリティ設定
- **ネットワーク**: インスタンスが接続される仮想ネットワーク
- **タグ** (tags): インスタンスを分類および検索するためのユーザー定義ラベル

これらの設定によって、インスタンスの属性と使用方法が決まります。イメージと Availability Zone を除く設定はインスタンスの作成後も変更できますが、一部のインスタンスタイプ (flavor) はインスタンスの作成後に変更することはできません。インスタンスタイプの変更については、[コンソール使用ガイドのインスタンスタイプ変更](./console-guide/#modify-flavor)を参照してください。

<a id="image"></a>
### インスタンスイメージ { #image }

イメージはオペレーティングシステムを格納した仮想ディスクです。NHN Cloud は現在、Debian、Ubuntu、Rocky、および Windows をサポートしています。

すべてのイメージはインスタンスの仮想ハードウェアで最適に動作するよう設定されており、NHN Cloud のセキュリティ検証を経ているため、安全に利用できます。イメージの詳細については、[イメージ概要](/Compute/Image/ja/overview/)を参照してください。

<a id="flavor"></a>
### Instance flavor { #flavor }

NHN Cloud は、お客様の用途に合わせたさまざまなインスタンスタイプを提供しています。運用するサービスやアプリケーションの特性に応じて、適切なタイプのインスタンスを作成できます。作成済みのインスタンスのタイプも Web コンソールで簡単に変更できます。

| タイプ    | 説明                                                                                                                                               |
| ------- |--------------------------------------------------------------------------------------------------------------------------------------------------|
| m2 | CPU とメモリをバランスよく設定したタイプです。サービスやアプリケーションの性能要件が明確でない場合に使用します。 |
| c2 | CPU の性能を高く設定したインスタンスタイプです。高性能な演算処理が必要な Web アプリケーションサーバーや分析システムに使用します。 |
| r2 | 他のリソースに比べてメモリの使用量が多い場合に使用できます。主にメモリデータベースやキャッシュサーバーに使用します。 |
| t2 | 低コストのインスタンスです。ワークロードが高くないサーバーに使用します。 |
| u2 | 最も低コストのインスタンスです。ワークロードが高くないサーバーに使用します。<br>ローカルブロックストレージを使用するため、他のインスタンスと比べて相対的に安定性が低くなりますが、低価格で利用できます。<br>このタイプのインスタンスは I/O 性能を保証しません。 |
| x1 | 高スペックの CPU とメモリをサポートするタイプです。高いパフォーマンスが必要なサービスやアプリケーションに使用します。 |

<a id="availability-zone"></a>
### Availability Zone { #availability-zone }

NHN Cloud は、物理ハードウェアの障害に備えるため、システム全体を複数の Availability Zone に分割しています。各 Availability Zone には、ストレージシステム、ネットワークスイッチ、ラック、電源装置がすべて独立して構成されています。1 つの Availability Zone 内で発生した障害は他の Availability Zone に影響しないため、サービス全体の可用性が向上します。インスタンスを複数の Availability Zone に分散して構築することで、サービスの可用性をさらに高めることができます。

異なる Availability Zone 間には、次のような特性があります。

- 複数の Availability Zone に分散して作成されたインスタンス間でネットワーク通信が可能であり、この際に発生するネットワーク使用料は課金されません。
- 同じ Availability Zone 内で作成されたインスタンス間ではブロックストレージを共有できますが、異なる Availability Zone 間ではブロックストレージを共有することはできません。
- 異なる Availability Zone 間でフローティング IP を共有できます。1 つの Availability Zone で障害が発生した場合でも、フローティング IP を別の Availability Zone に迅速に移動することで、障害時間を最小化できます。

<a id="key-pair"></a>
### Key-pair { #key-pair }

キーペアは、公開鍵基盤 ([PKI](https://ko.wikipedia.org/wiki/%EA%B3%B5%EA%B0%9C_%ED%82%A4_%EA%B8%B0%EB%B0%98_%EA%B5%AC%EC%A1%B0)、public key infrastructure) をベースとした SSH 公開鍵・秘密鍵のペアです。NHN Cloud で作成したインスタンスに接続するには、セキュリティ上脆弱なキーボード入力方式の ID/パスワード認証ではなく、キーペアを使用する必要があります。ユーザーはキーペアの秘密鍵を使用してログイン情報をエンコードし、インスタンスに送信して接続認証を受けた後、安全にインスタンスに接続できます。キーペアを使用したインスタンスへの接続方法については、[インスタンスへの接続方法](#how-to-access-instances)を参照してください。

キーペアはインスタンスの作成時に NHN Cloud コンソールで新規作成することも、お客様が作成したキーペアを登録して使用することもできます。キーペアの登録方法については、[コンソールガイドのキーペアのインポート](./console-guide/#import-key-pairs-windows)を参照してください。

> [注意]
> キーペアを新規作成すると、キーペアの秘密鍵がダウンロードされます。秘密鍵は再発行できないため、ダウンロードした秘密鍵は安全なディスクや USB ドライブなどに大切に保管してください。秘密鍵が外部に漏洩した場合、誰でもその秘密鍵を使用して該当インスタンスにアクセスできるため、慎重に管理する必要があります。

> [注記]
> キーペアはユーザーアカウントに割り当てられたリソースであるため、プロジェクトを削除しても削除されずに維持されます。

<a id="security-groups"></a>
### Security groups { #security-groups }

セキュリティグループは、インスタンスに送受信されるネットワークトラフィックを制御する仮想ファイアウォールです。セキュリティグループの詳細については、[VPC 概要](/Network/VPC/ja/overview/)を参照してください。

> [注記]
> デフォルトのセキュリティグループは、外部からのインバウンド (in-bound) ネットワークトラフィックをすべて無視するよう設定されています。SSH でインスタンスに接続する際は、インスタンスが属するセキュリティグループで SSH ポートを開放するよう設定した後、インスタンスに接続します。

<a id="network"></a>
### ネットワーク { #network }

インスタンスが外部と通信するには、VPC で定義されたネットワークに少なくとも 1 つ接続されている必要があります。ネットワークに接続されていないインスタンスにはアクセスできません。ネットワークを新規作成または変更するには、[VPC 概要](/Network/VPC/ja/overview/)を参照してください。

<a id="pricing"></a>
## 課金 { #pricing }

インスタンスの課金方式は次のとおりです。

* インスタンスは作成した瞬間から課金されます。
* インスタンスのルートブロックストレージは、インスタンスとは別にブロックストレージの課金基準で課金されます。
* インスタンスが停止すると、90 日間はホームページの料金基準から 90% 割引された金額が適用されます。停止状態が 90 日を超えると、停止状態を維持したまま通常料金に切り替わります。
* 終了したインスタンスは課金されません。

課金の詳細については、サービス別の[料金ページ](https://www.toast.com/kr/service/compute/instance#price)を参照してください。

<a id="regions-and-availability"></a>
## サポートリージョンおよび可用性 { #regions-and-availability }

インスタンスは NHN Cloud の複数のリージョンで利用でき、各リージョンは独立した Availability Zone で構成されています。リージョンの選択時には、サービス対象ユーザーの所在地、規制要件、および他の NHN Cloud サービスとの連携を考慮します。

- **韓国（板橋）リージョン**: 国内サービスに最も低いレイテンシーを提供します。
- **韓国（坪村）リージョン**: 板橋リージョンの災害復旧サイトとして活用するのに適しています。
- **日本リージョン**: 日本および東アジア地域のユーザーを対象としたサービスに適しています。

各リージョンで提供されるインスタンスタイプとイメージは異なる場合があるため、インスタンスを作成する前にコンソールのリージョン別サポートリストを確認します。

<a id="how-to-access-instances"></a>
## インスタンスへの接続方法 { #how-to-access-instances }

<a id="how-to-access-linux-instances"></a>
### Linux インスタンスへの接続方法 { #how-to-access-linux-instances }

Linux インスタンスに接続するには、SSH クライアントを使用します。インスタンスのセキュリティグループで SSH アクセスポート（デフォルト 22）が開放されていない場合、接続できません。SSH アクセスを許可する方法については、[VPC 概要](/Network/VPC/ja/overview/)を参照してください。インスタンスにフローティング IP が割り当てられていない場合、NHN Cloud 外部から接続することはできません。フローティング IP を割り当てる方法については、[VPC 概要](/Network/VPC/ja/overview/)を参照してください。

<a id="how-to-access-linux-instances-from-mac-or-linux-using-an-ssh-client"></a>
#### Mac または Linux の SSH クライアントで Linux インスタンスに接続するには

Mac や Linux には、通常 SSH クライアントがデフォルトでインストールされています。SSH クライアントで次のようにキーペアの秘密鍵を使用して接続します。

Ubuntu インスタンス

	$ ssh -i my_private_key.pem ubuntu@<インスタンスの IP>

Debian インスタンス

	$ ssh -i my_private_key.pem debian@<インスタンスの IP>

Rocky インスタンス

	$ ssh -i my_private_key.pem rocky@<インスタンスの IP>

<a id="how-to-access-linux-instances-from-windows-using-putty-ssh-client"></a>
#### Windows で PuTTY SSH クライアントを使用して Linux インスタンスに接続するには

PuTTY SSH クライアントは、Windows で広く使用されている SSH クライアントプログラムです。[PuTTY](https://www.chiark.greenend.org.uk/~sgtatham/putty/latest.html) または韓国語パッチが適用された [iPuTTY](https://github.com/iPuTTY/iPuTTY/releases/tag/l0.70i) をインストールします。

Windows で PuTTY SSH クライアントを使用して Linux インスタンスに接続するには、次の 3 つの手順を実行する必要があります。

* キーペアの秘密鍵を PuTTY 用の秘密鍵に変換
* PuTTY 用の秘密鍵を PuTTY に登録
* PuTTY でインスタンスに接続

##### 1. キーペアの秘密鍵を PuTTY 用の秘密鍵に変換

PuTTY では、キーペアの秘密鍵を PuTTY の秘密鍵形式に変換して使用する必要があります。キーの変換は、PuTTY とともにインストールされる puttygen を使用します。

![이미지1](http://static.toastoven.net/prod_instance/putty001.png)

**[PuTTY Key Generator]** ダイアログの下部にある **[パラメータ]** で **[生成するキーの種類]** を **[RSA]** に選択し、**[生成するキーのビット数]** はデフォルト値の「2048」ビットを入力します。**[操作]** の **[秘密鍵ファイルの読み込み]** の横にある **[読み込む]** ボタンをクリックし、キーペアの秘密鍵ファイルを読み込みます。

![이미지2](http://static.toastoven.net/prod_instance/putty002.png)

**[操作]** の **[生成されたキーの保存]** の横にある **[秘密鍵の保存]** ボタンをクリックして、PuTTY 用に変換されたキーペアの秘密鍵を保存します。**[キーのパスフレーズ]** を空白のままにして秘密鍵を保存すると、**「パスフレーズで保護せずにこのキーを保存しますか?」**というメッセージが表示されます。変換された秘密鍵をより安全に保存するには、パスフレーズを設定して保存します。

> [注意]
インスタンスに自動的にログインするように設定するには、パスフレーズを使用しないでください。パスフレーズを使用すると、ログイン時に秘密鍵のパスワードを直接入力する必要があります。

##### 2. PuTTY 用の秘密鍵を PuTTY に登録

このようにして作成された PuTTY 用の秘密鍵は、次の 2 つの方法で登録して使用できます。

* PuTTY で認証秘密鍵ファイルを登録して使用する方法
* pageant（PuTTY 認証エージェント）に認証秘密鍵ファイルを登録して使用する方法

**A. PuTTY で認証秘密鍵ファイルを登録して使用する方法**


PuTTY を起動し、左側の **[カテゴリ]** で **[接続] > [SSH] > [Auth]** を選択します。右側の **[認証パラメータ]** の下にある **[認証秘密鍵ファイル]** に PuTTY 用の秘密鍵を登録します。

![이미지3](http://static.toastoven.net/prod_instance/putty005.png)

秘密鍵を登録した後、接続情報を保存しておくと、毎回秘密鍵ファイルを再登録する必要がありません。接続情報を保存する方法については、以下の接続方法を参照してください。


**B. pageant（PuTTY 認証エージェント）に認証秘密鍵ファイルを登録して使用する方法**


PuTTY とともにインストールされる pageant を起動すると、次の図のように Windows トレイにアイコンが表示されます。pageant アイコンを右クリックして **[キーの追加]** メニューをクリックし、PuTTY 用の秘密鍵を追加します。

![이미지4](http://static.toastoven.net/prod_instance/putty006.png)

秘密鍵が追加されたことを確認するには、**[キーの表示]** を選択します。キーが正常に追加されている場合、次の図のように追加されたキーが表示されます。

![이미지5](http://static.toastoven.net/prod_instance/putty008.png)

pageant は一度起動すると Windows トレイに常駐するため、インスタンスに接続するたびに再起動する必要がありません。ただし、Windows を再起動した場合は、再度起動する必要があります。

##### 3. PuTTY でインスタンスに接続

PuTTY 用に変換された秘密鍵が正しく登録されていることを確認したら、PuTTY を起動します。

![이미지6](http://static.toastoven.net/prod_instance/putty009.png)

基本接続情報の **[ホスト名]** は次のように使用します。

Ubuntu

	ubuntu@<インスタンスの IP>

Debian

	debian@<インスタンスの IP>

Rocky

	rocky@<インスタンスの IP>

**[ポート]** は SSH のデフォルトポートである 22、**[接続タイプ]** は **[SSH]** を指定します。

すべての情報が正確であることを確認したら、セッションを保存します。**[読み込み、保存、保存されたセッションの削除]** の保存済みセッションの下のフィールドに保存するセッション名を入力し、**[保存]** ボタンをクリックしてセッションを保存します。セッションを保存しないと、手順 2-A で登録した秘密鍵の設定も維持されません。

**[開く]** をクリックすると、インスタンスに接続します。

<a id="how-to-access-windows-instances"></a>
### Windows インスタンスへの接続方法 { #how-to-access-windows-instances }

Windows サーバーに接続するには、NHN Cloud コンソールで接続先の Windows インスタンスを選択します。インスタンス詳細画面の **[接続情報]** タブで **[パスワードの確認]** ボタンをクリックして、Windows サーバーに設定されたパスワードを確認します。

**[パスワードの確認]** で入力するキーペアの秘密鍵は、サーバーには送信されず、ブラウザでパスワードを復号化する処理にのみ使用されます。

**[パスワードの確認]** の横にある **[接続]** ボタンをクリックして、リモートデスクトップ接続設定が保存された .rdp ファイルをダウンロードして実行すると、Windows サーバーに接続します。Windows サーバーの ID は `Administrator` で、パスワードは NHN Cloud コンソールで確認したパスワードを使用します。

<a id="how-to-connect-serial-console"></a>
### シリアルコンソールへの接続方法 { #how-to-connect-serial-console }

ブートの失敗やネットワーク設定の問題など、SSH クライアントを使用できない状況では、シリアルコンソールに接続してインスタンスにアクセスできます。

シリアルコンソール機能には、次の制約事項があります。

* インスタンスごとに 1 つのシリアルコンソール接続のみ可能であり、複数接続を試みた場合、正常に接続できない場合があります。
* 個人がアップロードしたイメージで作成したインスタンスおよび個人イメージで作成したインスタンスは、シリアルコンソール接続を保証しません。
* シリアルコンソール接続は最大 10 分間接続可能です。
* Windows インスタンスはシリアルコンソール機能をサポートしていません。
* 2026 年 1 月 27 日のリリース以前に作成したインスタンスは、**[インスタンスの停止]** 後に **[インスタンスの起動]** が必要です。**[インスタンスの再起動]** 機能では適用されません。

> [注意]
> シリアルコンソールでインスタンスに接続してブート方法を変更すると、ブートに失敗する場合があります。その結果に対する責任はユーザーにあります。
> 通常の状況では、SSH クライアントによる接続の使用をお勧めします。

<a id="change-grub-bootloader-settings"></a>
#### GRUB ブートローダーの設定変更

2024 年 11 月 26 日のリリース以前に作成したインスタンスでブートローダーを操作するには、GRUB の設定が必要です。

GRUB 設定ファイルを修正します。

```
$ sudo vi /etc/default/grub.d/50-cloudimg-settings.cfg
GRUB_TIMEOUT=3
GRUB_TERMINAL="console serial"
GRUB_SERIAL_COMMAND="serial --speed=9600 --unit=0 --word=8 --parity=no --stop=1"
```

変更した設定を適用します。OS によって GRUB 設定を適用するコマンドが異なる場合があります。

```
$ sudo update-grub
```
