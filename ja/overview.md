<a id="compute-instance-overview"></a>
## Compute > Instance > 概要 { #compute-instance-overview }

インスタンスは、仮想CPU、メモリ、ルートブロックストレージで構成された仮想サーバーです。このサーバーに顧客のサービスやアプリケーションをインストールし、NHN Cloudが提供するさまざまなサービスと組み合わせて使用します。

<a id="components"></a>
## インスタンスの構成要素 { #components }

インスタンスを構成する要素は次のとおりです。

- **イメージ**: インスタンスのオペレーティングシステムを含む仮想ディスク
- **タイプ**(flavor): インスタンスの仮想ハードウェアのパフォーマンス
- **可用性ゾーン**(AZ, availability zone): インスタンスが作成される物理的な場所
- **キーペア**(key-pair): インスタンスへのアクセス手段として使用されるキー
- **セキュリティグループ**(security groups): インスタンスのネットワークセキュリティ設定
- **ネットワーク**: インスタンスが接続される仮想ネットワーク

この情報に応じて、インスタンスの属性と使用方法が変わります。この情報のうち、イメージと可用性ゾーンを除いた設定は、インスタンス作成後にも変更できますが、一部のインスタンスタイプ(flavor)はインスタンス作成後に変更できません。インスタンスタイプの変更の詳細については、[コンソール使用ガイドのインスタンスタイプ変更](./console-guide/#modify-flavor)を参照してください。

<a id="image"></a>
### イメージ { #image }

イメージは、オペレーティングシステムを含む仮想ディスクです。NHN Cloudは現在、Debian、Ubuntu、RockyおよびWindowsをサポートしています。

すべてのイメージは、インスタンスの仮想ハードウェア上で最適に実行されるように設定されており、NHN Cloudのセキュリティ検証を通過しているため、安全に使用できます。イメージの詳細については、[イメージ概要](/Compute/Image/ja/overview/)を参照してください。

<a id="flavor"></a>
### インスタンスタイプ(Instance flavor) { #flavor }

NHN Cloudは、顧客の用途に適したさまざまなインスタンスタイプを提供しています。運用するサービスまたはアプリケーションの特性に応じて、適切なタイプのインスタンスを作成できます。既に作成されたインスタンスのタイプも、ウェブコンソールから簡単に変更できます。

| タイプ    | 説明                                                                                                                                               |
| ------- |--------------------------------------------------------------------------------------------------------------------------------------------------|
| m2 | CPUとメモリのバランスが取れたタイプです。サービスまたはアプリケーションのパフォーマンス要件が明確でない場合に使用します。                                                                               |
| c2 | CPUのパフォーマンスを高く設定したインスタンスタイプです。高性能な演算パフォーマンスが必要なウェブアプリケーションサーバーまたは分析システムに使用します。                                                                           |
| r2 | 他のリソースと比較してメモリの使用量が多い場合に使用できます。通常、メモリデータベースまたはキャッシュサーバーに使用します。                                                                               |
| t2 | 低コストのインスタンスです。ワークロードが高くないサーバーに使用します。                                                                                                          |
| u2 | 最も低コストのインスタンスです。ワークロードが高くないサーバーで使用します。<br>ローカルブロックストレージを使用しているため、相対的に他のインスタンスと比較して安定性は劣りますが、低廉な価格で利用できます。<br>このタイプのインスタンスはI/Oパフォーマンスを保証しません。 |
| x1 | 高スペックのCPUとメモリをサポートするタイプです。高いパフォーマンスが必要なサービスまたはアプリケーションに使用します。                                                                                        |

<a id="availability-zone"></a>
### 可用性ゾーン(Availability zone) { #availability-zone }

NHN Cloudは、物理ハードウェアの問題による障害に備えるため、システム全体を複数の可用性ゾーンに分割しています。各可用性ゾーンには、ストレージシステム、ネットワークスイッチ、ラック、電源装置がすべて個別に構成されています。1つの可用性ゾーン内で発生した障害は、他の可用性ゾーンに影響を与えないため、サービス全体の可用性が向上します。複数の可用性ゾーンにインスタンスを分散して構築すれば、サービスの可用性をさらに向上させることができます。

異なる可用性ゾーン間には、次のような特性があります。

- 複数の可用性ゾーンに分散して作成されたインスタンス間でネットワーク通信が可能であり、このときに発生するネットワーク使用コストは課金されません。
- 同じ可用性ゾーン内で作成されたインスタンス間ではブロックストレージを共有できますが、異なる可用性ゾーン間ではブロックストレージを共有できません。
- 異なる可用性ゾーン間でフローティングIPを共有できます。1つの可用性ゾーンで障害が発生した場合でも、フローティングIPを別の可用性ゾーンに迅速に移動して、障害時間を最小化できます。

<a id="key-pair"></a>
### キーペア(Key-pair) { #key-pair }

キーペアは、公開鍵基盤([PKI](https://ja.wikipedia.org/wiki/%E5%85%AC%E9%96%8B%E9%8D%B5%E5%9F%BA%E7%9B%A4), public key infrastructure)に基づくSSH公開鍵と秘密鍵のペアです。NHN Cloudで作成されたインスタンスにアクセスするには、セキュリティが低いキーボード入力方式のID/パスワード認証の代わりに、キーペアを使用する必要があります。ユーザーはキーペアの秘密鍵を使用してログイン情報をエンコードしてインスタンスに送信し、アクセス認証を受けた後、安全にインスタンスにアクセスできます。キーペアを使用したインスタンスへのアクセス方法については、[インスタンスへのアクセス方法](#how-to-access-instances)を参照してください。

キーペアは、インスタンスを作成する際にNHN Cloudコンソールで新規作成することも、顧客が直接作成したキーペアを登録して使用することもできます。キーペア登録方法については、[コンソールガイドのキーペアのインポート](./console-guide/#import-key-pairs-windows)を参照してください。

> [注意]
> キーペアを新規作成すると、キーペアの秘密鍵をダウンロードします。秘密鍵は再発行できないため、ダウンロードした秘密鍵は安全なディスクやUSBドライブなどに大切に保管してください。秘密鍵が外部に流出した場合、誰もが流出した秘密鍵を使用してそのインスタンスにアクセスできるため、慎重に管理する必要があります。

> [注記]
> キーペアはユーザーアカウントに割り当てられたリソースであるため、プロジェクトを削除してもキーペアは削除されず、保持されます。

<a id="security-groups"></a>
### セキュリティグループ(Security groups) { #security-groups }

セキュリティグループは、インスタンスに転送されるネットワークトラフィックを決定する仮想ファイアウォールです。セキュリティグループの詳細については、[VPC概要](/Network/VPC/ja/overview/)を参照してください。

> [注記]
> デフォルトセキュリティグループは、外部からの受信(in-bound)ネットワークトラフィックをすべて無視するように設定されています。SSHでインスタンスにアクセスする場合は、インスタンスが属するセキュリティグループでSSHポートを開くように設定してからインスタンスにアクセスしてください。

<a id="network"></a>
### ネットワーク { #network }

インスタンスが外部と通信するには、VPCで定義されたネットワークのうち、少なくとも1つ以上に接続されている必要があります。ネットワークに接続されていないインスタンスにはアクセスできません。ネットワークを新規作成または変更するには、[VPC概要](/Network/VPC/ja/overview/)を参照してください。

<a id="pricing"></a>
## 課金 { #pricing }

インスタンスの課金方式は次のとおりです。

* インスタンスは作成した時点から課金されます。
* インスタンスのルートブロックストレージは、インスタンスとは別にブロックストレージ課金基準で課金されます。
* インスタンスが停止すると、90日間はホームページ料金基準で90%割引された金額が適用されます。停止状態が90日を超える場合は、停止状態を維持しながら通常料金に変更されます。
* 終了したインスタンスは課金されません。

課金に関する詳細については、サービス別[料金ページ](https://www.toast.com/kr/service/compute/instance#price)を参照してください。

<a id="how-to-access-instances"></a>
## インスタンスへのアクセス方法 { #how-to-access-instances }

<a id="how-to-access-linux-instances"></a>
### Linuxインスタンスへのアクセス方法 { #how-to-access-linux-instances }

Linuxインスタンスにアクセスする場合は、SSHクライアントを使用します。インスタンスのセキュリティグループにSSHアクセスポート(デフォルト22)が開かれていない場合は、アクセスできません。SSHアクセスを許可する方法については、[VPC概要](/Network/VPC/ja/overview/)を参照してください。インスタンスにフローティングIPが割り当てられていない場合は、NHN Cloud外部からアクセスできません。フローティングIPを割り当てる方法については、[VPC概要](/Network/VPC/ja/overview/)を参照してください。

<a id="how-to-access-linux-instances-from-mac-or-linux-using-an-ssh-client"></a>
#### MacまたはLinuxのSSHクライアントでLinuxインスタンスにアクセスする方法

MacまたはLinuxには通常、SSHクライアントがデフォルトでインストールされています。SSHクライアントで、以下のようにキーペアの秘密鍵を使用してアクセスします。

Ubuntuインスタンス

	$ ssh -i my_private_key.pem ubuntu@<インスタンスのIP>

Debianインスタンス

	$ ssh -i my_private_key.pem debian@<インスタンスのIP>

Rockyインスタンス

	$ ssh -i my_private_key.pem rocky@<インスタンスのIP>

<a id="how-to-access-linux-instances-from-windows-using-putty-ssh-client"></a>
#### WindowsでPuTTY SSHクライアントを使用してLinuxインスタンスにアクセスする方法

PuTTY SSHクライアントは、Windowsで広く使用されているSSHクライアントプログラムです。[PuTTY](https://www.chiark.greenend.org.uk/~sgtatham/putty/latest.html)または日本語パッチが適用された[iPuTTY](https://github.com/iPuTTY/iPuTTY/releases/tag/l0.70i)をインストールします。

WindowsでPuTTY SSHクライアントを使用してLinuxインスタンスにアクセスするには、3つのステップを実行する必要があります。

* キーペアの秘密鍵をPuTTY用秘密鍵に変更
* PuTTY用秘密鍵をPuTTYに登録
* PuTTYでインスタンスにアクセス

##### 1. キーペアの秘密鍵をPuTTY用秘密鍵に変更

PuTTYではキーペア秘密鍵をPuTTYの秘密鍵形式に変更して使用する必要があります。鍵変換はPuTTYと共にインストールされるputtygenを使用します。

![イメージ1](http://static.toastoven.net/prod_instance/putty001.png)

**PuTTY Key生成ツール**ダイアログの一番下の**パラメータ**で**生成するキーの形式**を**RSA**として選択し、**生成するキーのビット数**はデフォルト値の「2048」ビットで入力します。**操作**の下の**秘密鍵ファイルを読み込む**の横にある**読み込む**ボタンをクリックし、キーペアの秘密鍵ファイルを読み込みます。

![イメージ2](http://static.toastoven.net/prod_instance/putty002.png)

**操作**の下の**生成されたキーを保存**の横にある**秘密鍵を保存**ボタンをクリックして、PuTTY用に変換されたキーペア秘密鍵を保存します。**キーパスフレーズ**を空欄のままにして秘密鍵を保存すると、**パスフレーズで保護せずにこのキーを保存しますか？**というメッセージが表示されます。変換された秘密鍵をより安全に保存するには、パスフレーズを設定して保存します。

> [注意]
> インスタンスに自動的にログインするように設定する場合は、パスフレーズを使用しないでください。パスフレーズを使用すると、ログイン時に秘密鍵のパスワードを直接入力する必要があります。

##### 2. PuTTY用秘密鍵をPuTTYに登録

このように作成されたPuTTY用秘密鍵は2つの方法で登録して使用できます。

* PuTTYで認証秘密鍵ファイルを登録して使用する方法
* pageant(PuTTY認証エージェント)に認証秘密鍵ファイルを登録して使用する方法

**A. PuTTYで認証秘密鍵ファイルを登録して使用する方法**


PuTTYを実行し、左側の**カテゴリ**から**Connection > SSH > Auth**を選択します。右側の**認証パラメータ**の下の**認証秘密鍵ファイル**にPuTTY用秘密鍵を登録します。

![イメージ3](http://static.toastoven.net/prod_instance/putty005.png)

秘密鍵を登録した後、アクセス情報を保存しておけば、毎回秘密鍵ファイルを再度登録する必要はありません。アクセス情報を保存する方法については、以下のアクセス方法を参照してください。


**B. pageant(PuTTY認証エージェント)に認証秘密鍵ファイルを登録して使用する方法**


PuTTYと共にインストールされるpageantを実行すると、以下の図のようにWindowsトレイにアイコンが表示されます。pageantアイコンを右クリックした後、**鍵の追加**メニューをクリックして、PuTTY用秘密鍵を追加します。

![イメージ4](http://static.toastoven.net/prod_instance/putty006.png)

秘密鍵が追加されたことを確認するには、**鍵を表示**を選択します。鍵が正常に追加されていれば、以下の図のように追加された鍵が表示されます。

![イメージ5](http://static.toastoven.net/prod_instance/putty008.png)

pageantは1度実行されると、Windowsトレイに常駐して実行されるため、インスタンスにアクセスするたびに再度実行する必要はありません。ただし、Windowsを新規に起動した場合は、再度実行する必要があります。

##### 3. PuTTYでインスタンスにアクセス

PuTTY用に変換された秘密鍵が正常に登録されている場合は、PuTTYを実行します。

![イメージ6](http://static.toastoven.net/prod_instance/putty009.png)

基本アクセス情報の**ホスト名**は、次のように使用します。

Ubuntu

	ubuntu@<インスタンスのIP>

Debian

	debian@<インスタンスのIP>

Rocky

	rocky@<インスタンスのIP>

**ポート**はSSHデフォルトポートの22、**接続タイプ**を**SSH**に指定します。

すべての情報が正確な場合は、セッションを保存します。**読み込む、保存、保存されたセッション削除**で保存されたセッションの下のフィールドに保存するセッション名を入力し、**保存**ボタンをクリックしてセッションを保存します。セッションを保存しない場合は、2-Aで登録した秘密鍵の設定も保持されません。

これで**開く**をクリックすると、インスタンスにアクセスします。

<a id="how-to-access-windows-instances"></a>
### Windowsインスタンスへのアクセス方法 { #how-to-access-windows-instances }

Windowsサーバーにアクセスするには、NHN CloudコンソールからアクセスするWindowsインスタンスを選択します。インスタンス詳細画面の**アクセス情報**タブで**パスワード確認**ボタンをクリックして、Windowsサーバーに設定されたパスワードを確認します。

**パスワード確認**で入力するキーペアの秘密鍵はサーバーに送信されず、ブラウザーでパスワードを復号化する処理にのみ使用されます。

**パスワード確認**の横にある**接続**ボタンをクリックして、リモートデスクトップアクセス設定が保存されている.rdpファイルを受け取って実行すると、Windowsサーバーにアクセスします。Windowsサーバーのユーザー名は`Administrator`で、パスワードはNHN Cloudコンソールで確認したパスワードを使用します。

<a id="how-to-connect-serial-console"></a>
### シリアルコンソールへのアクセス方法 { #how-to-connect-serial-console }

ブートの失敗やネットワーク構成の問題など、SSHクライアントを使用できない状況では、シリアルコンソールに接続してインスタンスにアクセスできます。

シリアルコンソール機能には、次の制限があります。

* インスタンスごとに1つのシリアルコンソール接続のみが可能であり、複数接続試行時は正常に接続されない場合があります。
* ユーザーがアップロードしたイメージから作成されたインスタンスと個人イメージから作成されたインスタンスでは、シリアルコンソールアクセスが保証されません。
* シリアルコンソール接続の最大接続時間は10分間です。
* Windowsインスタンスはシリアルコンソール機能をサポートしていません。
* 2026年1月27日の配布以前に作成されたインスタンスは、**インスタンスを停止**してから**インスタンスを起動**する必要があります。**インスタンスの再起動**機能では適用されません。

> [注意]
> シリアルコンソールでインスタンスにアクセスしてブート方法を変更する場合、ブートに失敗する可能性があり、その結果に関する責任はユーザーにあります。
> 一般的な状況では、SSHクライアントアクセスの使用をお勧めします。

<a id="how-to-connect-serial-console-change-grub-bootloader-settings"></a>
#### GRUBブートローダー設定の変更

2024年11月26日の配布以前に作成されたインスタンスでブートローダーを操作するには、GRUB設定が必要です。

GRUB設定ファイルを編集します。

```
$ sudo vi /etc/default/grub.d/50-cloudimg-settings.cfg
GRUB_TIMEOUT=3
GRUB_TERMINAL="console serial"
GRUB_SERIAL_COMMAND="serial --speed=9600 --unit=0 --word=8 --parity=no --stop=1"
````

変更された設定を適用します。OSによって、GRUB設定適用コマンドが異なる場合があります。

```
$ sudo update-grub
```
