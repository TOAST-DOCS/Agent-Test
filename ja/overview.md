## Compute > Instance > 概要

インスタンスは、仮想的な CPU、メモリ、ルートブロックストレージで構成される仮想サーバーです。このサーバーに顧客のサービスやアプリケーションをインストールし、NHN Cloud が提供する多様なサービスを組み合わせて使用します。インスタンスは数分で作成でき、必要に応じていつでも拡張または縮小できます。

<a id="components"></a>

## インスタンス構成要素

インスタンスを構成する要素は次のとおりです。

- **イメージ**: インスタンスのオペレーティングシステムを含む仮想ディスク
- **タイプ** (flavor): インスタンスの仮想ハードウェアのパフォーマンス
- **Availability Zone** (AZ): インスタンスが作成される物理的な場所
- **キーペア** (key-pair): インスタンスへのアクセス手段として使用されるキー
- **セキュリティグループ** (security groups): インスタンスのネットワークセキュリティ設定
- **ネットワーク**: インスタンスが接続される仮想ネットワーク
- **タグ** (tags): インスタンスを分類および検索するためのユーザー定義ラベル

この情報に従ってインスタンスの属性と使用方法が変わります。これらの情報のうち、イメージと Availability Zone を除いた設定はインスタンス作成後も変更できますが、一部のインスタンスタイプ (flavor) はインスタンス作成後に変更できません。インスタンスタイプの変更の詳細については、[コンソール使用ガイドのインスタンスタイプの変更](./console-guide/#modify-flavor)を参照してください。

<a id="image"></a>
### イメージ

イメージはオペレーティングシステムを含む仮想ディスクです。NHN Cloud は現在 Debian、Ubuntu、Rocky、および Windows をサポートしています。

すべてのイメージはインスタンスの仮想ハードウェアで最適に実行されるように構成されており、NHN Cloud のセキュリティ検証を通過しているため、安全に使用できます。イメージの詳細については、[イメージ概要](/Compute/Image/ja/overview/)を参照してください。

<a id="flavor"></a>
### インスタンスタイプ (Instance flavor)

NHN Cloud は顧客の使用目的に合わせた多様なインスタンスタイプを提供します。運用するサービスまたはアプリケーションの特性に応じて、適切なタイプのインスタンスを作成できます。既に作成されたインスタンスのタイプも Web コンソールから簡単に変更できます。

| タイプ    | 説明                                                                                                                                               |
| ------- |--------------------------------------------------------------------------------------------------------------------------------------------------|
| m2 | CPU とメモリのバランスが取れたタイプです。サービスまたはアプリケーションのパフォーマンス要件が明確でない場合に使用します。                                                                               |
| c2 | CPU のパフォーマンスが高く設定されたインスタンスタイプです。高性能演算が必要な Web アプリケーションサーバーまたは分析システムに使用します。                                                                           |
| r2 | 他のリソースと比較してメモリの使用量が多い場合に使用できます。通常はメモリデータベースまたはキャッシュサーバーに使用します。                                                                               |
| t2 | コストが低いインスタンスです。ワークロードが低いサーバーに使用します。                                                                                                          |
| u2 | 最も低コストのインスタンスです。ワークロードが低いサーバーで使用します。<br>ローカルブロックストレージを使用しているため、相対的に他のインスタンスと比較して安定性は低いですが、低価格で利用できます。<br>このタイプのインスタンスは I/O パフォーマンスを保証しません。 |
| x1 | 高性能の CPU とメモリをサポートするタイプです。高いパフォーマンスが必要なサービスまたはアプリケーションに使用します。                                                                                        |

<a id="availability-zone"></a>
### Availability Zone

NHN Cloud は物理ハードウェアの問題による障害に備えるため、システム全体を複数の Availability Zone に分割しています。この Availability Zone ごとに、ストレージシステム、ネットワークスイッチ、ラック、および電源装置がすべて個別に構成されています。1 つの Availability Zone 内で発生する障害は他の Availability Zone に影響を与えないため、サービス全体の可用性が向上します。インスタンスを複数の Availability Zone に分散して構築すると、サービスの可用性をさらに向上させることができます。

異なる Availability Zone 間には次の特性があります。

- 複数の Availability Zone に分散して作成されたインスタンス間でネットワーク通信が可能であり、この場合のネットワーク使用料金は請求されません。
- 同じ Availability Zone に作成されたインスタンス間ではブロックストレージを共有できますが、異なる Availability Zone 間ではブロックストレージを共有することはできません。
- 異なる Availability Zone でフローティング IP を共有できます。1 つの Availability Zone に障害が発生した場合でも、フローティング IP を別の Availability Zone にすばやく移動して、ダウンタイムを最小化することができます。

<a id="key-pair"></a>
### キーペア (Key-pair)

キーペアは公開鍵基盤 ([PKI](https://ja.wikipedia.org/wiki/%E5%85%AC%E9%96%8B%E9%8D%B5%E5%9F%BA%E7%9B%A4), public key infrastructure) に基づく SSH 公開鍵と秘密鍵のペアです。NHN Cloud で作成されたインスタンスにアクセスするには、セキュリティ上の脆弱性のあるキーボード入力方式のユーザー ID/パスワード認証の代わりにキーペアを使用する必要があります。ユーザーはキーペアの秘密鍵を使用してログイン情報をエンコードしてインスタンスに送信し、アクセス認証を受けた後、安全にインスタンスにアクセスできます。キーペアを使用したインスタンスへのアクセス方法については、[インスタンスへのアクセス方法](#how-to-access-instances)を参照してください。

キーペアはインスタンス作成時に NHN Cloud コンソールで新しく作成することもできますし、顧客が直接作成したキーペアを登録して使用することもできます。キーペアの登録方法については、[コンソールガイドのキーペアのインポート](./console-guide/#import-key-pairs-windows)を参照してください。

> [注意]
> キーペアを新しく生成する場合、キーペアの秘密鍵をダウンロードします。秘密鍵は再発行できないため、ダウンロードした秘密鍵は安全なディスクまたは USB ドライブなどに安全に保管してください。秘密鍵が外部に漏洩すると、誰でも漏洩した秘密鍵を使用して該当するインスタンスにアクセスできるため、慎重に管理する必要があります。

> [注記]
> キーペアはユーザーアカウントに割り当てられたリソースであるため、プロジェクトを削除してもキーペアは削除されず、保持されます。

<a id="security-groups"></a>
### セキュリティグループ (Security groups)

セキュリティグループはインスタンスに送信されるネットワークトラフィックを決定する仮想ファイアウォールです。セキュリティグループの詳細については、[VPC 概要](/Network/VPC/ja/overview/)を参照してください。

> [注記]
> デフォルトセキュリティグループは、外部からのインバウンドネットワークトラフィックをすべて無視するように設定されています。SSH でインスタンスにアクセスする場合は、インスタンスが属するセキュリティグループで SSH ポートを開くように設定してからインスタンスにアクセスします。

<a id="network"></a>
### ネットワーク

インスタンスが外部と通信するには、VPC で定義されたネットワークの少なくとも 1 つ以上に接続されている必要があります。ネットワークに接続されていないインスタンスにはアクセスできません。ネットワークを新しく作成または変更する場合は、[VPC 概要](/Network/VPC/ja/overview/)を参照してください。

<a id="pricing"></a>

## 課金

インスタンスの課金方式は次のとおりです。

* インスタンスは作成した瞬間から課金されます。
* インスタンスのルートブロックストレージはインスタンスとは別にブロックストレージの課金基準に従って課金されます。
* インスタンスが停止されると、90 日間はホームページの料金基準に基づいて 90% 割引された金額が適用されます。停止状態が 90 日を超えると、停止状態を維持しながら通常料金に変換されます。
* 終了したインスタンスは課金されません。

課金の詳細については、サービス別[料金ページ](https://www.toast.com/kr/service/compute/instance#price)を参照してください。

<a id="backup-and-snapshot"></a>

## バックアップとスナップショット

インスタンスのデータを安全に保護するには、定期的なバックアップとスナップショットの作成をお勧めします。バックアップとスナップショットには次のような違いがあります。

- **バックアップ (Backup)**: 指定されたスケジュールに従ってインスタンスのルートブロックストレージを定期的にコピーして、別のストレージに保管します。長期保管と災害復旧に適しています。
- **スナップショット (Snapshot)**: 特定の時点のインスタンス状態をそのまま保存します。システム変更前のロールバックポイントとして使用するのに適しています。

バックアップとスナップショットは元のインスタンスが削除されても保持されるため、削除後もこれらを使用してインスタンスを復元できます。詳細については、[バックアップサービス概要](/Storage/Backup/ja/overview/)を参照してください。

<a id="how-to-access-instances"></a>

## インスタンスへのアクセス方法

<a id="how-to-access-linux-instances"></a>
### Linux インスタンスへのアクセス方法

Linux インスタンスにアクセスする場合、SSH クライアントを使用します。インスタンスのセキュリティグループで SSH アクセスポート（デフォルト: 22）が開いていない場合、アクセスできません。SSH アクセスを許可する方法については、[VPC 概要](/Network/VPC/ja/overview/)を参照してください。インスタンスに浮動 IP が割り当てられていない場合、NHN Cloud の外部からアクセスできません。浮動 IP を割り当てる方法については、[VPC 概要](/Network/VPC/ja/overview/)を参照してください。

#### Mac または Linux の SSH クライアントで Linux インスタンスにアクセスする方法

Mac や Linux には、通常、SSH クライアントが既定でインストールされています。SSH クライアントで、以下のようにキーペアの秘密鍵を使用してアクセスします。

Ubuntu インスタンス

	$ ssh -i my_private_key.pem ubuntu@<インスタンスの IP>

Debian インスタンス

	$ ssh -i my_private_key.pem debian@<インスタンスの IP>

Rocky インスタンス

	$ ssh -i my_private_key.pem rocky@<インスタンスの IP>

#### Windows で PuTTY SSH クライアントを使用して Linux インスタンスにアクセスする方法

PuTTY SSH クライアントは、Windows で広く使用されている SSH クライアントプログラムです。[PuTTY](https://www.chiark.greenend.org.uk/~sgtatham/putty/latest.html) または日本語パッチが適用された [iPuTTY](https://github.com/iPuTTY/iPuTTY/releases/tag/l0.70i) をインストールします。

Windows で PuTTY SSH クライアントを使用して Linux インスタンスにアクセスするには、3 つのステップが必要です。

* キーペアの秘密鍵を PuTTY 用の秘密鍵に変換する
* PuTTY 用の秘密鍵を PuTTY に登録する
* PuTTY でインスタンスにアクセスする

##### 1. キーペアの秘密鍵を PuTTY 用の秘密鍵に変換する

PuTTY では、キーペアの秘密鍵を PuTTY の秘密鍵形式に変換して使用する必要があります。キーの変換は、PuTTY とともにインストールされる puttygen を使用します。

![イメージ1](http://static.toastoven.net/prod_instance/putty001.png)

**PuTTY Key ジェネレーター**ダイアログの最下部にある**パラメーター**で、**生成するキーの形式**を **RSA** に選択し、**生成するキーのビット数**は既定値の「2048」ビットで入力します。**操作**の**秘密鍵ファイルの読み込み**の横にある**読み込み**ボタンをクリックして、キーペアの秘密鍵ファイルを読み込みます。

![イメージ2](http://static.toastoven.net/prod_instance/putty002.png)

**操作**の**生成されたキーを保存**の横にある**秘密鍵を保存**ボタンをクリックして、PuTTY 用に変換されたキーペアの秘密鍵を保存します。**キーパスフレーズ**を空白のままにして秘密鍵を保存すると、**パスフレーズなしでこのキーを保存していますか？**というメッセージが表示されます。変換された秘密鍵をより安全に保存する場合は、パスフレーズを設定して保存します。

> [注意]
> インスタンスに自動的にログインするように設定する場合は、パスフレーズを使用しないでください。パスフレーズを使用する場合は、ログイン時に秘密鍵のパスワードを直接入力する必要があります。

```
#echo hello
```

##### 2. PuTTY 用の秘密鍵を PuTTY に登録する

このように作成された PuTTY 用の秘密鍵は、2 つの方法で登録して使用できます。

* PuTTY で認証秘密鍵ファイルを登録して使用する方法
* pageant（PuTTY 認証エージェント）に認証秘密鍵ファイルを登録して使用する方法

**A. PuTTY で認証秘密鍵ファイルを登録して使用する方法**

PuTTY を実行し、左側の**カテゴリー**で**接続 > SSH > Auth** を選択します。右側の**認証パラメーター**の**認証秘密鍵ファイル**に PuTTY 用の秘密鍵を登録します。

![イメージ3](http://static.toastoven.net/prod_instance/putty005.png)

秘密鍵を登録した後、接続情報を保存しておくと、毎回秘密鍵ファイルを再度登録する必要がなくなります。接続情報を保存する方法は、以下のアクセス方法を参照してください。

**B. pageant（PuTTY 認証エージェント）に認証秘密鍵ファイルを登録して使用する方法**

PuTTY とともにインストールされる pageant を実行すると、下の図のように Windows トレイにアイコンが表示されます。pageant アイコンを右クリックした後、**キーを追加**メニューをクリックして、PuTTY 用の秘密鍵を追加します。

![イメージ4](http://static.toastoven.net/prod_instance/putty006.png)

秘密鍵が追加されたことを確認するには、**キーの表示**を選択します。キーが正常に追加された場合、下の図のように追加されたキーが表示されます。

![イメージ5](http://static.toastoven.net/prod_instance/putty008.png)

pageant は一度実行されると、Windows トレイに継続して実行されたままになるため、インスタンスにアクセスするたびに再度実行する必要がありません。ただし、Windows を再起動した場合は、再度実行する必要があります。

##### 3. PuTTY でインスタンスにアクセスする

PuTTY 用に変換された秘密鍵が正常に登録されたら、PuTTY を実行します。

![イメージ6](http://static.toastoven.net/prod_instance/putty009.png)

基本的なアクセス情報の**ホスト名**は、以下のように使用します。

Ubuntu

	ubuntu@<インスタンスの IP>

Debian

	debian@<インスタンスの IP>

Rocky

	rocky@<インスタンスの IP>

**ポート**は SSH 既定ポートの 22、**接続形式**は **SSH** に指定します。

すべての情報が正確であれば、セッションを保存します。**セッションの読み込み、保存、削除**で、保存されたセッションの下にあるフィールドに保存するセッション名を入力し、**保存**ボタンをクリックしてセッションを保存します。セッションを保存しない場合、2-A で登録した秘密鍵の設定も保持されません。

これで**開く**をクリックするとインスタンスにアクセスします。

<a id="how-to-access-windows-instances"></a>
### Windows インスタンスへのアクセス方法

Windows サーバーにアクセスするには、NHN Cloud コンソールでアクセスする Windows インスタンスを選択します。インスタンスの詳細画面の**アクセス情報**タブで**パスワードの確認**ボタンをクリックして、Windows サーバーに設定されたパスワードを確認します。

**パスワードの確認**で入力するキーペアの秘密鍵はサーバーに送信されず、ブラウザーでパスワードを復号化する操作にのみ使用されます。

**パスワードの確認**の横の**接続**ボタンをクリックして、リモートデスクトップアクセス設定が保存された .rdp ファイルをダウンロードして実行すると、Windows サーバーにアクセスします。Windows サーバーのユーザー ID は `Administrator` であり、パスワードは NHN Cloud コンソールで確認したパスワードを使用します。

### シリアルコンソールアクセス方法

ブート失敗、ネットワーク構成の問題など、SSH クライアントを使用できない状況では、シリアルコンソールに接続してインスタンスにアクセスできます。

シリアルコンソール機能には、以下の制限があります。

* インスタンスごとに 1 つのシリアルコンソール接続のみが可能で、複数接続を試みた場合、正常に接続されない可能性があります。
* ユーザーがアップロードしたイメージから作成したインスタンスおよびプライベートイメージから作成したインスタンスは、シリアルコンソールアクセスを保証しません。
* シリアルコンソール接続は、最大 10 分間アクセスできます。
* Windows インスタンスはシリアルコンソール機能をサポートしていません。
* 2026 年 1 月 27 日の配布より前に作成されたインスタンスは、**インスタンスの停止**後に**インスタンスの開始**が必要です。**インスタンスの再起動**機能では適用されません。

> [注意]
> シリアルコンソールでインスタンスにアクセスしてブートロード方法を変更した場合、ブートに失敗する可能性があり、その結果の責任はユーザーにあります。
> 通常の状況では、SSH クライアントアクセスの使用をお勧めします。

#### GRUB ブートローダー設定の変更

2024 年 11 月 26 日の配布より前に作成されたインスタンスでブートローダーを操作するには、GRUB の設定が必要です。

GRUB 設定ファイルを修正します。

```
$ sudo vi /etc/default/grub.d/50-cloudimg-settings.cfg
GRUB_TIMEOUT=3
GRUB_TERMINAL="console serial"
GRUB_SERIAL_COMMAND="serial --speed=9600 --unit=0 --word=8 --parity=no --stop=1"
```

変更した設定を適用します。OS によって GRUB 設定の適用コマンドが異なる場合があります。

```
$ sudo update-grub
```
