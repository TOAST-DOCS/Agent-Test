<a id="compute-instance-overview"></a>
## Compute > Instance > 概要 { #compute-instance-overview }

インスタンスは、仮想 CPU、メモリ、ルートブロックストレージで構成された仮想サーバーです。このサーバーにお客様のサービスやアプリケーションをインストールし、NHN Cloud が提供するさまざまなサービスを組み合わせて使用します。インスタンスは数分以内に作成でき、必要に応じていつでも拡張または縮小できます。

<a id="components"></a>
## インスタンスの構成要素 { #components }

インスタンスを構成する要素は次のとおりです。

- **イメージ**: インスタンスのオペレーティングシステムを格納した仮想ディスク
- **タイプ** (flavor): インスタンスの仮想ハードウェア性能
- **可用性ゾーン** (AZ): インスタンスが作成される物理的な場所
- **キーペア** (key-pair): インスタンスへのアクセス手段として使用されるキー
- **セキュリティグループ** (security groups): インスタンスのネットワークセキュリティ設定
- **ネットワーク**: インスタンスが接続される仮想ネットワーク
- **タグ** (tags): インスタンスを分類・検索するためのユーザー定義ラベル

これらの情報に基づいて、インスタンスの属性と使用方法が決まります。これらの情報のうち、イメージと可用性ゾーンを除く設定はインスタンスの作成後も変更できますが、一部のインスタンスタイプ (flavor) はインスタンスの作成後に変更することはできません。インスタンスタイプの変更の詳細については、[コンソール使用ガイドのインスタンスタイプの変更](./console-guide/#modify-flavor)を参照してください。

<a id="image"></a>
### イメージ { #image }

イメージはオペレーティングシステムを格納した仮想ディスクです。NHN Cloud は現在、Debian、Ubuntu、Rocky、Windows をサポートしています。

すべてのイメージはインスタンスの仮想ハードウェアで最適に動作するよう設定されており、NHN Cloud のセキュリティ検証を経ているため、安全に使用できます。イメージの詳細については、[イメージの概要](/Compute/Image/ja/overview/)を参照してください。

<a id="flavor"></a>
### Instance Flavor { #flavor }

NHN Cloud はお客様の用途に合わせたさまざまなインスタンスタイプを提供します。運用するサービスまたはアプリケーションの特性に応じて、適切なタイプのインスタンスを作成できます。すでに作成済みのインスタンスのタイプも、Web コンソールで簡単に変更できます。

| タイプ    | 説明                                                                                                                                               |
| ------- |--------------------------------------------------------------------------------------------------------------------------------------------------|
| m2 | CPU とメモリをバランスよく設定したタイプです。サービスやアプリケーションの性能要件が明確でない場合に使用します。 |
| c2 | CPU の性能を高く設定したインスタンスタイプです。高性能な演算処理が必要な Web アプリケーションサーバーや分析システムに使用します。 |
| r2 | 他のリソースと比較してメモリの使用量が多い場合に使用できます。通常、メモリデータベースやキャッシュサーバーに使用します。 |
| t2 | コストが低いインスタンスです。ワークロードが高くないサーバーに使用します。 |
| u2 | 最もコストが低いインスタンスです。ワークロードが高くないサーバーで使用します。<br>ローカルブロックストレージを使用するため、他のインスタンスと比べて相対的に安定性が低くなりますが、低価格で利用できます。<br>このタイプのインスタンスは I/O 性能を保証しません。 |
| x1 | 高性能の CPU とメモリをサポートするタイプです。高い性能が必要なサービスやアプリケーションに使用します。 |

<a id="availability-zone"></a>
### Availability Zone { #availability-zone }

NHN Cloud は、物理ハードウェアの障害に備えるため、システム全体を複数の Availability Zone に分割しています。各 Availability Zone では、ストレージシステム、ネットワークスイッチ、ラック、電源装置がそれぞれ独立して構成されています。ある Availability Zone 内で発生した障害は他の Availability Zone に影響を与えないため、サービス全体の可用性が向上します。インスタンスを複数の Availability Zone に分散して構築することで、サービスの可用性をさらに高めることができます。

異なる Availability Zone 間には次のような特性があります。

- 複数の Availability Zone に分散して作成されたインスタンス間でネットワーク通信が可能であり、その際に発生するネットワーク使用料は課金されません。
- 同じ Availability Zone 内に作成されたインスタンス間ではブロックストレージを共有できますが、異なる Availability Zone 間ではブロックストレージを共有することはできません。
- 異なる Availability Zone 間でフローティング IP を共有できます。ある Availability Zone で障害が発生した場合でも、フローティング IP を別の Availability Zone に迅速に移動することで、障害時間を最小限に抑えることができます。

<a id="key-pair"></a>
### Key-pair { #key-pair }

キーペアは公開鍵基盤 ([PKI](https://ko.wikipedia.org/wiki/%EA%B3%B5%EA%B0%9C_%ED%82%A4_%EA%B8%B0%EB%B0%98_%EA%B5%AC%EC%A1%B0)、public key infrastructure) を基にした SSH 公開鍵・秘密鍵のペアです。NHN Cloud で作成したインスタンスに接続するには、セキュリティ上脆弱なキーボード入力方式による ID/パスワード認証の代わりに、キーペアを使用する必要があります。ユーザーはキーペアの秘密鍵を使用してログイン情報をエンコードし、インスタンスに送信して接続認証を受けた後、安全にインスタンスにアクセスできます。キーペアを使用したインスタンスへの接続方法については、[インスタンスへの接続方法](#how-to-access-instances)を参照してください。

キーペアはインスタンスを作成する際に NHN Cloud コンソールで新規作成することも、お客様が独自に作成したキーペアを登録して使用することもできます。キーペアの登録方法については、[コンソールガイドのキーペアのインポート](./console-guide/#import-key-pairs-windows)を参照してください。

> [注意]
> キーペアを新規作成すると、キーペアの秘密鍵がダウンロードされます。秘密鍵は再発行できないため、ダウンロードした秘密鍵は安全なディスクや USB ドライブなどに保管してください。秘密鍵が外部に漏洩すると、誰でも漏洩した秘密鍵でそのインスタンスにアクセスできるため、慎重に管理する必要があります。

> [注記]
> キーペアはユーザーアカウントに割り当てられたリソースであるため、プロジェクトを削除しても削除されずに保持されます。

<a id="security-groups"></a>
### Security Groups { #security-groups }

セキュリティグループはインスタンスに送受信されるネットワークトラフィックを制御する仮想ファイアウォールです。セキュリティグループの詳細については、[VPC の概要](/Network/VPC/ja/overview/)を参照してください。

> [注記]
> デフォルトのセキュリティグループは、外部からのインバウンド (in-bound) ネットワークトラフィックをすべて拒否するよう設定されています。SSH でインスタンスに接続する場合は、インスタンスが属するセキュリティグループに SSH ポートを開放するよう設定した後、インスタンスに接続します。

<a id="network"></a>
### ネットワーク { #network }

インスタンスが外部と通信するには、VPC で定義されたネットワークのうち少なくとも 1 つに接続されている必要があります。ネットワークに接続されていないインスタンスにはアクセスできません。ネットワークを新規作成または変更するには、[VPC の概要](/Network/VPC/ja/overview/)を参照してください。

<a id="pricing"></a>
## 課金 { #pricing }

インスタンスの課金方式は次のとおりです。

* インスタンスは作成した瞬間から課金されます。
* インスタンスのルートブロックストレージは、インスタンスとは別にブロックストレージの課金基準で課金されます。
* インスタンスが停止されると、90 日間はホームページの料金基準から 90% 割引された金額が適用されます。停止状態が 90 日を超えると、停止状態のまま通常料金に切り替わります。
* 終了したインスタンスは課金されません。

課金の詳細については、サービスごとの[料金ページ](https://www.toast.com/kr/service/compute/instance#price)を参照してください。

<a id="backup-and-snapshot"></a>
## バックアップとスナップショット { #backup-and-snapshot }

インスタンスのデータを安全に保護するため、定期的なバックアップとスナップショットの作成をお勧めします。バックアップとスナップショットには次のような違いがあります。

- **バックアップ (Backup)**: 指定されたスケジュールに従い、インスタンスのルートブロックストレージを定期的にコピーして別のストレージに保管します。長期保管と災害復旧に適しています。
- **スナップショット (Snapshot)**: 特定の時点におけるインスタンスの状態をそのまま保存します。システム変更前のロールバックポイントとして使用するのに適しています。

バックアップとスナップショットは、元のインスタンスが削除されても保持されるため、削除後もこれらを使用してインスタンスを復元できます。詳細については、[バックアップサービスの概要](/Storage/Backup/ja/overview/)を参照してください。

<a id="how-to-access-instances"></a>
## インスタンスへの接続方法 { #how-to-access-instances }

<a id="how-to-access-linux-instances"></a>
### Linux インスタンスへの接続方法 { #how-to-access-linux-instances }

Linux インスタンスに接続する際は、SSH クライアントを使用します。インスタンスのセキュリティグループで SSH 接続ポート（デフォルト 22）が開放されていない場合、接続できません。SSH 接続を許可する方法については、[VPC 概要](/Network/VPC/ja/overview/)を参照してください。インスタンスにフローティング IP が割り当てられていない場合、NHN Cloud 外部からは接続できません。フローティング IP を割り当てる方法については、[VPC 概要](/Network/VPC/ja/overview/)を参照してください。

<a id="mac-linux-ssh-linux"></a>
#### Mac または Linux の SSH クライアントで Linux インスタンスに接続する方法

Mac や Linux には通常、SSH クライアントがデフォルトでインストールされています。SSH クライアントから、以下のようにキーペアの秘密鍵を使用して接続します。

Ubuntu インスタンス

	$ ssh -i my_private_key.pem ubuntu@<インスタンスのIP>

Debian インスタンス

	$ ssh -i my_private_key.pem debian@<インスタンスのIP>

Rocky インスタンス

	$ ssh -i my_private_key.pem rocky@<インスタンスのIP>

<a id="windows-putty-ssh-linux"></a>
#### Windows で PuTTY SSH クライアントを使用して Linux インスタンスに接続する方法

PuTTY SSH クライアントは、Windows で広く使用されている SSH クライアントプログラムです。[PuTTY](https://www.chiark.greenend.org.uk/~sgtatham/putty/latest.html) または韓国語パッチが適用された [iPuTTY](https://github.com/iPuTTY/iPuTTY/releases/tag/l0.70i) をインストールします。

Windows で PuTTY SSH クライアントを使用して Linux インスタンスに接続するには、3 つのステップを実行する必要があります。

* キーペアの秘密鍵を PuTTY 用の秘密鍵に変換する
* PuTTY 用の秘密鍵を PuTTY に登録する
* PuTTY でインスタンスに接続する

##### 1. キーペアの秘密鍵を PuTTY 用の秘密鍵に変換する

PuTTY では、キーペアの秘密鍵を PuTTY の秘密鍵形式に変換して使用する必要があります。鍵の変換には、PuTTY と一緒にインストールされる puttygen を使用します。

![イメージ1](http://static.toastoven.net/prod_instance/putty001.png)

**[PuTTY Key 生成器]** ダイアログの一番下にある **[パラメータ]** で、**[生成する鍵の種類]** を **[RSA]** に選択し、**[生成する鍵のビット数]** にはデフォルト値の「2048」ビットを入力します。**[操作]** の下にある **[秘密鍵ファイルの読み込み]** の横の **[読み込み]** ボタンをクリックし、キーペアの秘密鍵ファイルを読み込みます。

![イメージ2](http://static.toastoven.net/prod_instance/putty002.png)

**[操作]** の下にある **[生成された鍵の保存]** の横の **[秘密鍵を保存]** ボタンをクリックし、PuTTY 用に変換されたキーペアの秘密鍵を保存します。**[鍵のパスフレーズ]** を空欄のまま秘密鍵を保存すると、**パスフレーズで保護せずにこのキーを保存しますか?** というメッセージが表示されます。変換された秘密鍵をより安全に保存するには、パスフレーズを設定して保存します。

> [注意]
インスタンスに自動でログインするよう設定するには、パスフレーズを使用しないでください。パスフレーズを使用すると、ログイン時に秘密鍵のパスワードを直接入力する必要があります。


```
#echo hello
```

##### 2. PuTTY 用の秘密鍵を PuTTY に登録する

このようにして作成した PuTTY 用の秘密鍵は、2 つの方法で登録して使用できます。

* PuTTY で認証秘密鍵ファイルを登録して使用する方法
* pageant（PuTTY 認証エージェント）に認証秘密鍵ファイルを登録して使用する方法

**A. PuTTY で認証秘密鍵ファイルを登録して使用する方法**


PuTTY を起動し、左側の **[カテゴリ]** で **[接続 > SSH > Auth]** を選択します。右側の **[認証パラメータ]** の下にある **[認証秘密鍵ファイル]** に PuTTY 用の秘密鍵を登録します。

![イメージ3](http://static.toastoven.net/prod_instance/putty005.png)

秘密鍵を登録した後、接続情報を保存しておくと、毎回秘密鍵ファイルを再登録する必要がありません。接続情報を保存する方法については、以下の接続手順を参照してください。


**B. pageant（PuTTY 認証エージェント）に認証秘密鍵ファイルを登録して使用する方法**


PuTTY と一緒にインストールされる pageant を起動すると、以下の図のように Windows のトレイにアイコンが表示されます。pageant のアイコンを右クリックし、**[鍵の追加]** メニューをクリックして PuTTY 用の秘密鍵を追加します。

![イメージ4](http://static.toastoven.net/prod_instance/putty006.png)

秘密鍵が追加されたことを確認するには、**[鍵の表示]** を選択します。鍵が正しく追加されている場合は、以下の図のように追加された鍵が表示されます。

![イメージ5](http://static.toastoven.net/prod_instance/putty008.png)

pageant は一度起動すると、Windows のトレイに残り続けて実行されるため、インスタンスに接続するたびに再起動する必要はありません。ただし、Windows を再起動した場合は、再度起動する必要があります。

##### 3. PuTTY でインスタンスに接続する

PuTTY 用に変換された秘密鍵が正しく登録されている場合は、PuTTY を起動します。

![イメージ6](http://static.toastoven.net/prod_instance/putty009.png)

基本接続情報の **[ホスト名]** は次のように使用します。

Ubuntu

	ubuntu@<インスタンスのIP>

Debian

	debian@<インスタンスのIP>

Rocky

	rocky@<インスタンスのIP>

**[ポート]** は SSH のデフォルトポートである 22、**[接続タイプ]** は **[SSH]** に指定します。

すべての情報が正確な場合は、セッションを保存します。**[読み込み、保存、保存済みセッションの削除]** の **[保存済みセッション]** の下のフィールドに保存するセッション名を入力し、**[保存]** ボタンをクリックしてセッションを保存します。セッションを保存しない場合、2-A で登録した秘密鍵の設定も維持されません。

**[開く]** をクリックすると、インスタンスに接続します。

<a id="how-to-access-windows-instances"></a>
### Windows インスタンスへの接続方法 { #how-to-access-windows-instances }

Windows サーバーに接続するには、NHN Cloud コンソールで接続する Windows インスタンスを選択します。インスタンス詳細画面の **[接続情報]** タブで **[パスワードの確認]** ボタンをクリックし、Windows サーバーに設定されたパスワードを確認します。

**[パスワードの確認]** で入力するキーペアの秘密鍵はサーバーに送信されず、ブラウザでパスワードを復号する処理にのみ使用されます。

**[パスワードの確認]** の横にある **[接続]** ボタンをクリックして、リモートデスクトップ接続設定が保存された .rdp ファイルをダウンロードして実行すると、Windows サーバーに接続します。Windows サーバーの ID は `Administrator` であり、パスワードは NHN Cloud コンソールで確認したパスワードを使用します。

<a id="how-to-access-instances-1"></a>
### シリアルコンソールへの接続方法 { #how-to-access-instances-1 }

ブート失敗やネットワーク設定の問題など、SSH クライアントを使用できない状況でシリアルコンソールに接続して、インスタンスにアクセスできます。

シリアルコンソール機能には、次の制約事項があります。

* インスタンスごとに 1 つのシリアルコンソール接続のみ可能であり、複数同時接続を試みた場合、正常に接続できない場合があります。
* 個人がアップロードしたイメージで作成したインスタンスおよび個人イメージで作成したインスタンスは、シリアルコンソール接続を保証しません。
* シリアルコンソールの接続は最大 10 分間可能です。
* Windows インスタンスはシリアルコンソール機能をサポートしていません。
* 2026年1月27日のリリース以前に作成したインスタンスは、**[インスタンスの停止]** 後に **[インスタンスの起動]** が必要です。**[インスタンスの再起動]** 機能では適用されません。

> [注意]
> シリアルコンソールでインスタンスに接続してブート方法を変更した場合、ブートに失敗する可能性があり、その結果に対する責任はユーザーが負います。
> 通常の状況では、SSH クライアントによる接続の使用をお勧めします。

<a id="grub"></a>
#### GRUB ブートローダー設定の変更

2024年11月26日のリリース以前に作成したインスタンスでブートローダーを操作するには、GRUB の設定が必要です。

GRUB 設定ファイルを編集します。

```
$ sudo vi /etc/default/grub.d/50-cloudimg-settings.cfg
GRUB_TIMEOUT=3
GRUB_TERMINAL="console serial"
GRUB_SERIAL_COMMAND="serial --speed=9600 --unit=0 --word=8 --parity=no --stop=1"
```

変更した設定を適用します。OS によって GRUB 設定の適用コマンドが異なる場合があります。

```
$ sudo update-grub
```
