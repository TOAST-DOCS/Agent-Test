## インスタンスの作成 { #create-instances }

下記の設定を使用してインスタンスを作成するか、インスタンステンプレート (Instance Template) を通じてインスタンスを作成できます。インスタンステンプレートを通じてインスタンスを作成する場合は、インスタンス作成画面で**[インスタンステンプレートを使用]**を選択します。インスタンステンプレートの作成方法は、[インスタンステンプレートコンソールガイド](/Compute/Instance%20Template/ja/console-guide/)を参照してください。

![インスタンス作成ガイド表紙](../static/images/image-1704.jpg)

<a id="os-settings"></a>
### OS設定 { #os-settings }

インスタンス作成時に使用されるルートブロックストレージの作成方式を決定します。

- **新規作成および設定**または**既存リソース指定**のいずれかを選択します。
- **新規作成および設定**を選択した場合は、イメージを使用してルートブロックストレージを作成します。
- **既存リソース指定**を選択した場合は、既存に作成されたブロックストレージまたはスナップショットを使用します。

<a id="image"></a>
### イメージ { #image }

希望するオペレーティングシステムがインストールされたイメージを選択します。イメージはNHN Cloudが提供するパブリックイメージ、既存に作成されたユーザーイメージ、共有イメージから選択できます。

使用するイメージに応じてインスタンスタイプ (flavor) が異なるため、インスタンス作成時には最初にイメージを選択して進めることをお勧めします。

| オペレーティングシステム | ブロックストレージ | メモリ |
| --- | --- | --- |
| Linux<br>Ubuntu、Debian、Rocky | 20GB 以上 | 1GB 以上 |
| Windows | 50GB 以上 | 2GB 以上 |

<a id="root-block-storage"></a>
### ルートブロックストレージ { #root-block-storage }

**OS設定**に応じてルートブロックストレージを設定します。

- **新規作成および設定**を選択した場合は、**ブロックストレージタイプ**および**ブロックストレージサイズ**を指定してルートブロックストレージを作成します。
- **既存リソース指定**を選択した場合は、**ソースリソース**を指定してルートブロックストレージとして使用します。

<a id="root-block-storage-original-resource"></a>
#### ソースリソース

既存に作成された**ブロックストレージ**または**スナップショット**のいずれかを選択できます。

- **ブロックストレージ**を選択した場合は、既存に作成されたブロックストレージをルートブロックストレージとして使用します。
- **スナップショット**を選択した場合は、既存に作成されたスナップショットを使用してルートブロックストレージを作成します。

<a id="root-block-storage-block-storage-size"></a>
#### ブロックストレージサイズ

インスタンスのルートブロックストレージサイズを決定します。

- ブロックストレージサイズは、イメージが必要とする最小サイズ以上で作成する必要があります。

インスタンスのルートブロックストレージサイズは、インスタンスタイプに応じて異なります。

| タイプ | サポートされるブロックストレージサイズ |
| --- | --- |
| u2 タイプ | 20〜100 GB (タイプごとに固定) |
| t2、m2、c2、r2、x1 タイプ | 20〜2000GB |

> [注記]
> ブロックストレージサイズに応じて料金が発生するため、デフォルトブロックストレージのサイズを無条件に大きく作成することは非効率的です。必要に応じてブロックストレージを追加して使用することをお勧めします。
> **OS設定**で**既存リソース指定**を**ブロックストレージ**として選択した場合、ブロックストレージサイズの変更はできません。
> **OS設定**で**既存リソース指定**を**スナップショット**として選択した場合、ブロックストレージサイズは、ソースブロックストレージサイズ以上に設定する必要があります。

<a id="root-block-storage-block-storage-type"></a>
#### ブロックストレージタイプ

インスタンスのデフォルトブロックストレージタイプを決定します。

- **HDD**または**SSD**のいずれかを選択します。タイプに応じて、料金と性能が異なります。
- 一度選択したブロックストレージタイプは変更できません。

> [注記] 
> **OS設定**で**既存リソース指定**を選択した場合、ブロックストレージタイプの変更はできません。

<a id="availability-zone"></a>
### 可用性ゾーン { #availability-zone }

可用性ゾーンを明示的に設定しない場合は、任意のゾーンに設定されます。可用性ゾーンに応じて、このインスタンスが使用できるブロックストレージが決まります。使用するブロックストレージが特定の可用性ゾーンに存在する場合は、該当する可用性ゾーンに設定して使用します。

> [注記] 
> VPCのリソースはすべての可用性ゾーンで使用できます。
> **OS設定**で**既存リソース指定**を選択した場合、可用性ゾーンは変更できません。

可用性ゾーンの詳細については、[インスタンス概要の可用性ゾーン](./overview/#availability-zone)を参照してください。

<a id="flavor"></a>
### タイプ (flavor) { #flavor }

仮想ハードウェアの性能に応じて、さまざまなタイプを選択できます。ただし、イメージが必要とする仮想ハードウェアの性能に応じて、選択できるタイプが制限される場合があります。詳細については、[インスタンス概要](./overview)を参照してください。

> [注記]
> 1 vCPUは、スレッド1つとコア1つで構成されたソケット1つを意味し、ソケット1つあたりのスレッド数とコア数は、それぞれ1つで一定です。

インスタンスのタイプは、作成後もNHN Cloudコンソールで変更できます。高いタイプから低いタイプへの変更も可能で、低いタイプから高いタイプへの変更も可能です。一部のタイプは変更できない場合もあるため、詳細については[インスタンスタイプの変更](./console-guide/#modify-flavor)を参照してください。

> [注意] インスタンスのルートブロックストレージはタイプ変更で変更することはできません。

<a id="number-of-instances"></a>
### インスタンス数 { #number-of-instances }

イメージ、可用性ゾーン、タイプ、ブロックストレージサイズ、キーペア、ネットワーク設定がすべて同じインスタンスを複数作成する場合に使用します。インスタンスの名前は、設定した名前の後に`-1`、`-2`のような番号が付いて作成されます。たとえば、インスタンス名を`my-instance`にして2個作成した場合、`my-instance-1`、`my-instance-2`が作成されます。一度に作成できるインスタンスの最大数は10個です。

任意の可用性ゾーンに複数のインスタンスを作成した場合、各インスタンスは任意の可用性ゾーンに作成されます。たとえば、2個のインスタンスを任意の可用性ゾーンで作成した場合、2個が同じ可用性ゾーンに作成されることもあれば、異なる可用性ゾーンに作成されることもあります。すべてのインスタンスが同じ可用性ゾーンに作成されるべき場合は、特定の可用性ゾーンを選択して作成します。

> [注記]
> **OS設定**で**既存リソース指定**を**ブロックストレージ**として選択した場合、または**ネットワーク設定**で**既存ネットワークインターフェース指定**を選択した場合は、インスタンス数は`1`に制限されます。

<a id="key-pair"></a>
### キーペア { #key-pair }

既存のキーペアを使用するか、新しいキーペアを作成して使用します。既存のキーペア登録については、Windowsユーザーの場合は[キーペアのインポート (Windowsユーザー)](./console-guide/#import-key-pairs-windows)、MacおよびLinuxユーザーの場合は[キーペアのインポート (Mac、Linuxユーザー)](./console-guide/#import-key-pairs-mac-and-linux)を参照してください。

> [注記]
> キーペアはユーザーアカウントに割り当てられたリソースであるため、プロジェクトを削除してもキーペアは削除されず、保持されます。

<a id="network"></a>
### ネットワーク { #network }

VPCで定義されたサブネットの中から、インスタンスに接続するサブネットを選択します。サブネットを1つ選択するたびに、インスタンスにそのサブネットに接続されるネットワークインターフェースが作成されます。選択されたサブネットの順序を変更して、ネットワークインターフェースを変更することもできます。この場合、最初のネットワークインターフェース (`eth0`) がデフォルトゲートウェイとして設定されます。

ネットワークの作成と管理の詳細については、[VPC概要](/Network/VPC/ja/overview/)を参照してください。

<a id="floating-ip"></a>
### フローティング IP { #floating-ip }

インスタンス作成後にフローティング IPの使用有無を指定します。フローティング IP使用を選択した場合は、フローティング IPを新しく作成して、最初のネットワークインターフェースに接続します。この場合、最初のネットワークインターフェースは、インターネットゲートウェイが設定されたサブネットに接続されている必要があります。

フローティング IP管理は、インスタンス > 管理ページまたはインスタンス > フローティング IPページでも実行できます。フローティング IPの詳細については、[VPCコンソール使用ガイド](/Network/VPC/ja/console-guide/)を参照してください。

<a id="security-group"></a>
### セキュリティグループ { #security-group }

インスタンスが属するセキュリティグループを指定します。1つのインスタンスは複数のセキュリティグループに属することができます。インスタンスが複数のセキュリティグループに属する場合は、以下を参照してください。

- 各セキュリティグループに属するすべてのインスタンスとネットワーク通信が可能です。他のインスタンスの意図しないアクセスを防ぐ必要がある機密データを持つインスタンスの場合は、セキュリティグループを慎重に指定する必要があります。
- 各セキュリティグループのすべてのルールが統合されて、該当するインスタンスの外部通信に適用されます。

セキュリティグループの詳細については、[VPCコンソール使用ガイド](/Network/VPC/ja/console-guide/)を参照してください。

<a id="additional-block-storage"></a>
### 追加ブロックストレージ { #additional-block-storage }

インスタンス作成後に追加ブロックストレージの接続有無を指定します。追加ブロックストレージ使用を選択した場合は、ルートブロックストレージとは別の新しいブロックストレージを作成してインスタンスに接続します。ルートブロックストレージと同様に、追加ブロックストレージを作成する際に、名前、ストレージタイプ、サイズを指定できます。

ルートブロックストレージはOS用途のみに使用し、追加ブロックストレージに頻繁に使用するアプリケーションやデータを保管する場合は、ブロックストレージの接続/切断またはスナップショット機能を通じて、簡単に移行または複製できます。また、インスタンス障害が発生した場合は、追加ブロックストレージのみを切断した後、別のインスタンスに接続して、簡単にサービスを復旧できます。

ブロックストレージ管理は、インスタンス > ブロックストレージページでも実行できます。ブロックストレージの詳細については、[ブロックストレージガイド](/Storage/Block%20Storage/ja/overview/)を参照してください。

<a id="placement-policy"></a>
### 配置ポリシー { #placement-policy }

配置ポリシーを使用して、インスタンスを異なるハイパーバイザーに配置できます。インスタンス作成時に配置ポリシーを設定した場合、同じ配置ポリシーに割り当てられたインスタンスは異なるハイパーバイザーに作成されます。

> [注意]
> 分散配置が不可能な状況の場合は、インスタンス作成に失敗する可能性があります。

<a id="user-script"></a>
### ユーザースクリプト { #user-script }

インスタンス作成後に実行するスクリプトを指定します。ユーザースクリプトは、インスタンスの最初のブート完了後、ネットワーク設定などの初期化処理が終了した後に実行されます。NHN Cloudのユーザースクリプトは、公式イメージに組み込まれたcloud-init (Linux)、Cloudbase-init (Windows)などの自動化ツールによって実行されます。

> [注意]
> ユーザースクリプトはroot (Linux)/Administrator (Windows)ユーザー権限で実行されます。

<a id="user-script-linux"></a>
#### Linux

ユーザースクリプトの最初の行は、必ず`#!`で始まる必要があります。
```
#!/bin/bash
...
```

ユーザースクリプトが正常に動作するためには、インスタンス内部のログファイルを確認する必要があります。スクリプトの標準出力/エラーデバイスに出力したログは、`/var/log/cloud-init-output.log`で確認できます。

<a id="user-script-windows"></a>
#### Windows

Windowsイメージでは、ユーザースクリプト形式としてBatchスクリプト形式、Powershellスクリプト形式の両方をサポートしています。各形式は、最初の行に記述されたディレクティブによって区別されます。

* Batchスクリプト
```
rem cmd
...
```

* PowerShellスクリプト
```
#ps1_sysnative
...
```

BatchスクリプトとPowerShellスクリプトを一緒に使用したい場合は、以下のように記述します。

* EC2形式
```
<script>
...
</script>
<powershell>
...
</powershell>
```

ユーザースクリプトのログは、`C:\Program Files\Cloudbase Solutions\Cloudbase-Init\log\cloudbase-init`で確認できます。

ユーザースクリプトに関する詳細については、[cloud-init](https://cloudinit.readthedocs.io/en/latest/topics/format.html)または[Cloudbase-init](https://cloudbase-init.readthedocs.io/en/latest/userdata.html)ガイドを参照してください。

<a id="change-instance-status"></a>
### インスタンス状態の変更 { #change-instance-status }

インスタンスの停止、終了、削除、起動により、インスタンス状態を変更できます。

インスタンスの停止、終了、削除のハイパーバイザー リソースおよび料金情報については、以下の表を参照してください。

| 区分 | インスタンスの停止 | インスタンスの終了 | インスタンスの削除 |
| --- | -- | --- | --- |
| ハイパーバイザー リソース | リソース割り当て状態を維持 | リソースを返納し、インスタンス起動時に再割り当て | リソースを削除 |
| インスタンス料金 | 停止料金ポリシーを適用 | 無料 | 無料 |
| 接続された他のリソース料金 | 課金される | 課金される | 課金される |

> [注記] GPU Instance は終了できず、停止時にも通常（100%）の料金が発生します。

<a id="create-image"></a>
### イメージの作成 { #create-image }

インスタンスのルート ブロックストレージからイメージを作成します。イメージの作成はデータ整合性を保証するため、インスタンスを停止した状態で実行することをお勧めします。

インスタンスのルート ブロックストレージに空き容量がない場合、イメージの作成は可能ですが、イメージを他のインスタンスで使用するための初期化作業ができないため、正常に使用することはできません。イメージを作成する前に、インスタンスで最小 100 KB の空き容量を確保する必要があります。

作成されたイメージは **Compute > Image** に Private イメージとして登録されます。登録されたイメージを使用して、元のインスタンスと同じ ブロックストレージを持つインスタンスを作成できます。

> [注意]
> 作成されたイメージのサイズは、ルート ブロックストレージの実際の使用量より大きくなる可能性があります。

<a id="associatedisassociate-floating-ip"></a>
### Floating IP の関連付けと関連付け解除 { #associatedisassociate-floating-ip }

インスタンスの状態に関わらず、Floating IP をアタッチおよびデタッチできます。利用可能な Floating IP がない場合、または目的の Floating IP がない場合は、**[作成]** ボタンをクリックして Floating IP を作成してアタッチできます。または **[Network > VPC > Floating IP]** で Floating IP を作成して使用することもできます。

Floating IP の詳細については、「[VPC 概要](/Network/VPC/ja/overview/)」を参照してください。

<a id="modify-security-group"></a>
### セキュリティグループの変更 { #modify-security-group }

インスタンスの状態に関わらず、インスタンスのセキュリティグループを変更できます。変更されたセキュリティグループはすぐに適用されます。

セキュリティグループの詳細については、「[セキュリティグループ](./console-guide/#security-group)」および「[VPC 概要](/Network/VPC/ja/overview/)」を参照してください。

<a id="change-network-subnet"></a>
### ネットワークサブネットの変更 { #change-network-subnet }

インスタンスのネットワークサブネットは、インスタンスが停止している状態でのみ変更できます。サブネットを追加すると、そのサブネットに接続されるネットワークインターフェイスが自動的にインスタンスに作成されます。この場合、複数のサブネットを一度に追加すると、インスタンスに新たに作成されるネットワークインターフェイスの順序は任意に指定されます。サブネットをインスタンスから削除すると、作成されたネットワークインターフェイスも自動的に削除されます。

<a id="modify-flavor"></a>
### インスタンスタイプの変更 { #modify-flavor }

インスタンスタイプはインスタンスを停止した後に変更できます。インスタンスが実行中の場合は、**[追加機能]** の **[インスタンス停止]** をクリックしてインスタンスを停止します。

現在のタイプに応じて、変更可能なインスタンスタイプが異なります。

* m2、c2、r2、t2、x1 タイプのインスタンスは、m2、c2、r2、t2、x1 タイプのインスタンスタイプに変更できます。
* m2、c2、r2、t2、x1 タイプのインスタンスは、u2 タイプのインスタンスタイプに変更することはできません。
* u2 タイプは作成後にタイプを変更することはできません。同じ u2 タイプのインスタンスタイプへの変更もできません。

インスタンスタイプを変更すると、変更作業と変更確認作業が実行されます。すべての作業が完了すると、VM 状態が **Shutoff** 状態になり、**[追加機能]** の **[インスタンスの起動]** をクリックしてインスタンスを起動できます。

> [注記] インスタンスのルート ブロックストレージサイズは変更できません。インスタンスの ブロックストレージ容量が不足している場合は、ブロックストレージを追加して使用します。詳細については、「[ブロックストレージ概要](/Storage/Block%20Storage/ja/overview/)」を参照してください。

インスタンスは変更時点を基準として、変更されたタイプで課金されます。

<a id="change-instance-os-details"></a>
### インスタンス OS 情報の変更 { #change-instance-os-details }

インスタンスの状態に関わらず、インスタンス OS 情報を変更できます。

**[Compute > Instance]** サービスページで、OS 情報を変更するインスタンスをクリックします。該当するインスタンスの詳細情報画面の **[基本情報]** タブで **[OS > 変更]** をクリックします。

> [注記] OS 区分は変更できません。

<a id="change-instance-description"></a>
### インスタンス説明の変更 { #change-instance-description }

インスタンスの状態に関わらず、インスタンス説明を変更できます。

**[Compute > Instance]** サービスページで、説明を変更するインスタンスをクリックします。該当するインスタンスの詳細情報画面の **[基本情報]** タブで **[説明 > 変更]** をクリックします。

<a id="change-instance-key-pair"></a>
### インスタンスキーペアの変更 { #change-instance-key-pair }

インスタンスキーペアはインスタンスがアクティブ状態の場合にのみ変更できます。

**[Compute > Instance]** サービスページで、キーペア情報を変更するインスタンスをクリックします。該当するインスタンスの詳細情報画面の **[基本情報]** タブで **[キーペア > 変更]** をクリックします。

インスタンスのデフォルト アカウントのキーペアを選択したキーペアに変更します。インスタンスのデフォルト アカウントはインスタンス下部の詳細情報画面の **[接続情報]** タブで確認できます。

> [注意] インスタンスキーペアの変更時に、選択したキーペア以外のインスタンス内のすべての公開キー内容が削除されます。

> [注記] 基本インフラストラクチャサービスの ADMIN 権限を持つプロジェクトメンバーのみがインスタンスキーペアを変更でき、Windows OS インスタンスの場合は変更できません。

> [注記] インスタンスの作成に使用したイメージバージョンが古い場合、キーペア変更機能がサポートされない可能性があります。

<a id="manage-placement-policies"></a>
### 配置ポリシー管理 { #manage-placement-policies }

配置ポリシーを作成および削除でき、配置ポリシーに割り当てられたインスタンス一覧を表示します。

分散配置用の `anti-affinity` 配置ポリシータイプのみを提供します。

配置ポリシーにインスタンスが割り当てられている場合でも、配置ポリシーの削除が可能であり、この場合インスタンスは削除されません。

### キーペアのインポート(Windows ユーザー) { #import-key-pairs-windows }

PuTTY SSH クライアントをインストールすると、一緒にインストールされる puttygen プログラムでキーペアを生成し、NHN Cloud に登録して使用できます。

[PuTTY](https://www.chiark.greenend.org.uk/~sgtatham/putty/latest.html) または Korean patch が適用された [iPuTTY](https://github.com/iPuTTY/iPuTTY/releases/tag/l0.70i) をインストールします。

puttygen を実行します。

![イメージ1](http://static.toastoven.net/prod_instance/putty-ssh-001.png)

**パラメータ** で **RSA**(または古いバージョンの puttygen では SSH-2 RSA)を選択します。**アクション** の **生成** ボタンをクリックします。キーを生成するために、空いているスペース内でマウスを継続的に移動します。

キーが生成されると、以下の図のように公開キー ファイルの内容が表示されます。公開キーの内容全体を **キーペアのインポート** の **公開 Key:** 入力フィールドに貼り付けて、キーペアを登録します。

![イメージ1](http://static.toastoven.net/prod_instance/putty-ssh-002.png)

**アクション** の **秘密キーを保存** ボタンをクリックして、秘密キーを保存します。キー パスフレーズを空のままにして秘密キーを保存すると、**パスフレーズで保護されていないこのキーを保存しますか？** というメッセージが表示されます。変換された秘密キーをより安全に使用するには、パスフレーズを設定して保存します。

> [注意]
インスタンスに自動的にログインするには、パスフレーズを使用しないでください。パスフレーズを使用すると、ログイン時に秘密キーのパスワードを直接入力する必要があります。

登録したキーペアはインスタンスを作成するときに使用でき、インスタンスにアクセスする場合は、このキーペアの秘密キーでアクセスする必要があります。インスタンスのアクセス方法は、[インスタンスのアクセス方法](./overview/#how-to-access-instances) を参照してください。

NHN Cloud で生成されたキーペアと同様に、このように作成されたキーペアの秘密キーも外部に漏洩した場合、誰でも漏洩した秘密キーで対応するインスタンスにアクセスできるようになるため、慎重に管理する必要があります。

<a id="appendix-2-change-routing-in-windows"></a>

## 付録 2. Windows ルーティングの変更 { #appendix-2-change-routing-in-windows }

NHN Cloud Windows でルーティングを変更する方法は、次のような方法があります。

* スタート > ファイル名を指定して実行 > cmd

Route コマンド

* 現在の設定を出力 : route print
* 追加 : route add "宛先" mask "サブネット" "ゲートウェイ" metric "Metric 値" if "インターフェイス番号"
* 変更 : route change "宛先" mask "サブネット" "ゲートウェイ" metric "Metric 値" if "インターフェイス番号"
* 削除 : route delete "宛先" mask "宛先サブネット" "ゲートウェイ" metric "Metric 値" if "インターフェイス番号"
* オプション : -p (永続的なルートを指定)

説明

![イメージ1](http://static.toastoven.net/prod_instance/windows_route1.png)

* Metric 値 : 値が低いほど優先度が高い
* インターフェイス番号 : route print で確認可能 (赤い枠)
* 永続的なルート : -p オプションを使用しない場合、システムが再起動されるときに設定されたルートが初期化されるため、使用します (青い枠)

Case 1 - 特定のインターフェイスのみ外部通信を設定

* route change コマンドを使用して、外部通信を希望しないインターフェイス ルートのメトリックを変更するか、固定 IP 設定でデフォルト ゲートウェイ情報を入力しない方法などがあります。
* Metric 変更方法
    * インターフェイスのメトリックを増加

            $ route change 0.0.0.0 mask 0.0.0.0 172.16.5.1 metric 10 if 14 -p

![イメージ1](http://static.toastoven.net/prod_instance/windows_route2.png)

* 固定 IP 設定方法
    1. ipconfig /all を使用して IP 情報を確認
![イメージ1](http://static.toastoven.net/prod_instance/windows_route3.png)
    2. 確認された IP 情報を使用して、IP 設定ウィンドウでデフォルト ゲートウェイを除いて入力
![イメージ1](http://static.toastoven.net/prod_instance/windows_route4.png)
    3. route print を使用して確認
![イメージ1](http://static.toastoven.net/prod_instance/windows_route5.png)

Case 2 - 特定の範囲に対するルート設定

* route add コマンドを使用して、特定の範囲に対するルートを設定します。

        $ route add 172.16.0.0 mask 255.255.0.0 172.16.5.1 metric 1 if 14 -p

![イメージ1](http://static.toastoven.net/prod_instance/windows_route6.png)

Case 3 - 特定のルートを削除

* route delete を使用して、指定されたルートを削除します。

        $ route delete 172.16.0.0 mask 255.255.0.0 172.16.5.1

![イメージ1](http://static.toastoven.net/prod_instance/windows_route7.png)

<a id="appendix-4-restarting-instances-for-hypervisor-maintenance"></a>

## 付録 4. ハイパーバイザー メンテナンスのためのインスタンスの再起動ガイド { #appendix-4-restarting-instances-for-hypervisor-maintenance }

NHN Cloud は、基盤となるインフラ サービスのセキュリティと安定性を向上させるために、ハイパーバイザー ソフトウェアを定期的に更新しています。
メンテナンス対象のハイパーバイザーで実行中のインスタンスは、再起動を通じてメンテナンスが完了したハイパーバイザーに移動する必要があります。

インスタンスを再起動するには、コンソール経由でインスタンス名の横に生成された **[! 再起動]** ボタンを使用する必要があります。
`コンソール内のインスタンスの再起動またはオペレーティング システムの再起動機能では、インスタンスが別のハイパーバイザーに移動しません。`
以下のガイドに従って、コンソール内の再起動機能を使用してください。

メンテナンス対象として指定されたインスタンスがあるプロジェクトに移動します。

**1. メンテナンス対象インスタンスを確認します。**

インスタンス名の前に **[! 再起動]** ボタンがあるインスタンスがメンテナンス対象インスタンスです。
**[! 再起動]** ボタンにマウス カーソルを移動すると、詳細なメンテナンス スケジュールを確認できます。
![インスタンス メンテナンス イメージ1](http://static.toastoven.net/prod_instance/instance_p_migration_ko_1.png)    

**2. メンテナンス対象インスタンスで実行中のアプリケーションを無効化または終了します。**

メンテナンス対象インスタンスで実行中のアプリケーションを無効化または終了して、サービスに影響を与えないようにする必要があります。 
サービスに影響を与えざるを得ない場合は、NHN Cloud のカスタマー センターにお問い合わせいただければ、適切な対策をご案内させていただきます。

**3. メンテナンス対象インスタンス名の横にある [! 再起動] ボタンをクリックします。**

![インスタンス メンテナンス イメージ2](http://static.toastoven.net/prod_instance/instance_p_migration_ko_2.png)

**4. インスタンスの再起動を確認するウィンドウが表示されたら、[OK] ボタンをクリックします。**

![インスタンス メンテナンス イメージ3](http://static.toastoven.net/prod_instance/instance_p_migration_ko_3.png)

**5. インスタンス ステータス インジケーターが緑色に変わり、[! 再起動] ボタンが消えるまで待機します。**

インスタンス ステータス インジケーターが変わらないか、**[! 再起動]** ボタンが無効化されない場合は、「更新」を試してください。

インスタンスが再起動している間、対応するインスタンスに対して何の操作もできません。
インスタンスの再起動が正常に完了しない場合、自動的に管理者に報告され、NHN Cloud からは別途ご連絡させていただきます。
