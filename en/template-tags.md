## Sample > Template tag format collection { #sample-template-tags }

This document is a fixture for verifying that mkdocs-macros template tags still build after translation, and that the **Korean strings** that authors insert inside the tags are translated. The tags in the `$[ product_name ]$` document are taken directly from actual user guides (Private-DNS, Storage-Object-Storage, Storage-Online-NAS, nhn-cloud-foundry).

<a id="tt-set-literal"></a>
### Korean strings stored in variables { #tt-set-literal }

The `set` block at the top of the document stores different values in variables depending on the build environment. The region covered by this guide is $[ region_names ]$, and the API host is `$[ api_host ]$`.

| Item | Value | Note |
|---|---|---|
| Region | $[ region_names ]$ | Varies by environment |
| API host | `$[ api_host ]$` | A variable name that contains underscores |
| Query start time | {{executionTime}} | A placeholder that the workflow engine replaces |

### Tags inside code blocks { #tt-fenced }

Because mkdocs-macros processes tags inside code blocks with Jinja as well, you must wrap the tags with `{% raw %}` **to show them as examples**. If you do not wrap them, conditions are evaluated and variables are substituted, making the example disappear.

{% raw %}
```jinja
{% if "gov" in build_flags %}

{% endif %}
$[ region_names ]$ / {{ column name }} / $[ api_host ]$
```
{% endraw %}
