## Sample > Template tag examples { #sample-template-tags }

This document is a fixture to verify that mkdocs-macros template tags build even after translation, and that **Korean strings** embedded by authors inside tags are translated. The tags in the `$[ product_name ]$` document are taken as-is from actual user guides (Private-DNS, Storage-Object-Storage, Storage-Online-NAS, nhn-cloud-foundry).

<a id="tt-set-literal"></a>
### Korean strings in variables { #tt-set-literal }

The `set` blocks at the top of the document assign different values to variables depending on the build environment. The regions covered by this guide are $[ region_names ]$, and the API host is `$[ api_host ]$`.

| Classification | Value | Notes |
|---|---|---|
| Region | $[ region_names ]$ | Varies by environment |
| API host | `$[ api_host ]$` | Variable name containing underscores |
| Query start time | {{executionTime}} | Placeholder substituted by the workflow engine |

<a id="tt-fenced"></a>
### Tags inside code blocks { #tt-fenced }

mkdocs-macros processes tags inside code blocks as Jinja as well, so to **show tags as examples**, you must wrap them with `{% raw %}`. If you don't wrap them, the conditional statement is evaluated and variables are substituted, making the examples disappear.

{% raw %}
```jinja
{% if "gov" in build_flags %}
  {%- set region_names = "Korea (Pangyo) region" -%}
{% endif %}
$[ region_names ]$ / {{ column name }} / $[ api_host ]$
```
{% endraw %}
